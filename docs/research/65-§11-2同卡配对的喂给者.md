## 一、起点：I47 的形状，和它旁边那句话

`pairing_conflict`（`operator_agent/placement.py`）与 `oracle.evaluate` 里那道拒评都在，
spine-review P3-16 还专门把这条检查「搬进了库里，不能只活在测试文件里」。但它读的两个参数
`candidate_device` / `baseline_device` 是 `evaluate(...)` 的**显式入参**，而全仓的生产调用者
（`verifier.py:1255` 那一处）**不传**。于是：

- 真机上「两臂同卡」是**结构保证**：`benchmark_with_baselines` 在**一次**远端调用里跑完候选
  与基线（交错计时），载荷里只有一个 `device`；
- 检查因此**从没被触发过** —— 它既没抓到过什么，也没有任何东西在它该响的时候会响。

更难看的在旁边一行。同一个 `metrics.update` 里写着：

    "measurement_scope": "same_remote_device",

这个键名**就是 §11-2 要求的那件事**（同机同卡），而它当时是**写死的字面量**：全仓唯一的
读者是 `tests/test_p0_3.py` 里一条断言它等于这个字符串的用例。也就是说，产物里那句「同机同卡」
既不是声明（契约里另有一处 `same_device`），也不是观测，而是一句**没有任何东西在背后的话**。
message 里同一件事也写死了：`(同机同卡 median, 要求 >= …)` —— 而 message 是唯一保证被
Fixer/Search 的 prompt、报告和人眼看到的通道。

## 二、修法：把结构保证变成观测（四处，一层一层）

1. **远端按臂采身份**（`remote_scripts/run_kernel.py`）。新增 `_arm_identity()`，在
   `_bench_pair_interleaved` 里**每臂各在自己第一块计时前**读一次，写进
   `paired["arm_identity"] = {candidate, baseline, after}`。

   位置是判据的一部分，所以有守卫盯着顺序：**两次读必须在两臂之间**，不能都在循环开头各读
   一次 —— 否则「候选块跑完、基线块跑之前有人改了当前设备」就看不见，而那正是这条检查要抓
   的东西。（第一版就是那样写的，被自己新加的守卫抓出来，见 §四变异表。）

2. **控制端把身份压成可比较标签**（`placement.observed_pairing`）。压标签的口径只有这一处，
   返回 `(候选标签, 基线标签, scope)`，三种 scope：

   | scope | 含义 | 谁写 |
   |---|---|---|
   | `same_remote_device` | 两臂观测到同一张卡 | 观测 |
   | `cross_device_refused` | 观测到不同卡 ⇒ 该读数作废 | 观测 |
   | `unobserved` | 远端没报逐臂身份（老载荷/非远端路径）⇒ **不声称**同卡 | 观测 |

   `metrics["measurement_scope"]` 改成读它（不再是字面量），`arm_identity` 原样落盘
   （可审计），喂给 oracle 的 `arm_device_labels` 是**发布进 metrics 的那同一份**值 ——
   「判定看的必须就是产物里记的那份」是 verifier 自己写过的纪律。

3. **收口点拒评**（oracle 已有的那道检查，现在真的有输入）。跨卡时：资格全 False、
   `validity=uninformative`、`reasons=["pairing_conflict"]`（稳定 token；人话仍在 `refused`）。
   给 `reasons` 加 token 是为了让 verifier 不必从中文措辞里猜发生了什么 —— 措辞改一个字
   不该让判决跟着变。

4. **「通过」也不许立**。跨卡加速比**没有指称对象**，与 §4.3 规则 3 同族，所以
   `passed=False`。这**不是**把资格那件事判两遍：资格位（这个数被允许造成什么后果）仍然
   **只**由 oracle 判；这里判的是另一件事 —— 「passed 有没有对象」（与 `l3_pass_is_refused`
   刻意不折进 `can_gate` 是同一处分）。两处读的是同一对标签，所以不可能分叉 —— 这条写成了
   性质测试：`bool(pairing_conflict(c, b)) == (scope == SCOPE_CROSS)` 对身份笛卡尔积恒成立。

   顺带把 I46 的形状堵上：**拒评时发布的档位换成收口点的答案**。否则会出现
   `measurement_validity=valid` 与 `eligibility` 全 False 并排 —— 同一个 metrics 里两句话
   打架，正是那次真机抓到 I46 的病。三个用途位用 `dataclasses.replace(...).as_metrics()`
   重新摊平，不手写映射（档位→用途只有一处实现，就是那三个 property）。

## 三、为什么身份必须三件一起带（`visible_index` 不是卡号）

`_arm_identity()` 报的是 `visible_index` + `name` + `cuda_visible_devices`：

    CUDA_VISIBLE_DEVICES=2 → torch.cuda.current_device() == 0，而物理卡是 2

doc 63 §四那次事故正是栽在这里：`CUDA_VISIBLE_DEVICES=2 cd X && …python` 是**前缀赋值**，
只作用于内建的 `cd`，于是变量没进环境、占位落在 **GPU 0** —— 而现场每一条读数都自洽
（卡 2 的 util 序列 23 个 0、`validity=valid`、拆除 `quiescent`）。

所以标签里必须同时含 `visible_index` 与 `cuda_visible_devices`：只看 index，会把
「`=2` 下的 index 0」与「`=5` 下的 index 0」读成同一张卡。这条有专门用例。

⚠️ 但要**明写它管不到什么**：两个 arm 都在同一个进程里（同一次 `CUDA_VISIBLE_DEVICES`），
所以这次改动**抓不到**上面那次事故（那次两侧都是 0）。它抓的是另一类：两臂之间改了设备、
未来把两臂拆成两次调用、缓存基线拼接。要让「我们以为在卡 2 而进程在卡 0」也能被抓，需要的
是**观测卡 vs 租约卡**的检查，而 `placement.plan_leases` / `DeviceLease` 至今**零生产调用者**
（登记在设计 §15「没有实现物」表里）。这件**没有**被本次改动顺带解决。

## 四、守卫与变异（16 条用例，5 处变异全红）

| 变异 | 变红的用例 |
|---|---|
| 删掉 oracle 的 `candidate_device`/`baseline_device` 喂给 | `test_a_cross_card_observation_voids_the_number` |
| `measurement_scope` 退回写死 `"same_remote_device"` | `test_without_an_observation_…`（+ 同卡那条） |
| 跨卡不再拒 `passed` | `test_a_cross_card_observation_voids_the_number` |
| 标签里去掉 `visible=` 映射 | `test_the_same_index_under_a_different_visible_map_is_cross` |
| 远端不报 `arm_identity`（源头断） | `test_the_identity_survives_the_return_trip` |

成对/性质用例：同卡 ⇒ 照旧通过且不动资格位 ⇄ 跨卡 ⇒ 拒评且 `passed=False` ⇄ 没观测 ⇒
既不拒评也不自称同卡；`device_label` 对 6 种不可用输入一律 `None`（**空串会变成一次恒真
比较**）；`visible=2` 与 `visible=5` 同 index ⇒ 跨卡；标签与判决不许分叉（笛卡尔积性质）；
CPU 两臂配对成立但「是不是真卡」由 oracle 的规则 3 管（两件事共用一个键会让读者把
「同 CPU」读成「在真卡上测过」）；远端顺序守卫（两次读必须在两臂计时之间）；
`_arm_identity` 读失败时返回 `None` + 原因而**不是**猜一个 0。

## 五、这一趟**没有**覆盖的（明写）

1. **真机没有复跑。** 这次改的是远端脚本与控制端，离线守卫用的是假载荷。而且必须说清楚：
   **没有任何真机证据表明曾经发生过跨卡事故** —— 真机上是「一次调用一张卡」的结构保证。
   本次的价值是把它从「结构上不可能」变成「**有观测、且观测在产物里**」，不是发现了一个既有
   错误。`_arm_identity` 的 CUDA 分支在控制机上只能验到「读失败 ⇒ None + 原因」。
2. **窗口那一半仍无喂给者。** `pairing_conflict` 的窗口比较要求两侧都非 None，而
   `candidate_window` 是心跳窗口 id。把同一个 id 抄给 `baseline_window` 会让那道比较**恒真**
   （一次永远不响的守卫），所以**没抄**。等真有逐臂窗口观测再接 —— 登记在 I47 残留项里。
3. **`plan_leases` / `DeviceLease` 仍零生产调用者**（观测卡 vs 租约卡那类检查没有实现物）。
4. **`measurement_scope` 的取值域变了**（新增两个取值）。全仓唯一的按字面读它的地方是
   `tests/test_p0_3.py`，已跟着改；下游若有人按老字面比较这个键，需要知道这件事。
5. **CPU 上 scope 也会是 `same_remote_device`** —— 它回答的是「两臂同不同卡」，不是「这是不是
   一张真卡」。后者是 oracle 规则 3 的活（有用例钉住这两件事不共用一个键）。
