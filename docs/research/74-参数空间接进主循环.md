# 参数空间接进主循环：候选队列、顺位实例化、臂的身份（CHECKLOG I62）

上一片（doc 73 / I61）把「点 → 源码」补上了，但控制器**没有消费**它：`refuse_unconsumed_space`
每轮都拒绝，理由是「实例化那段已经就绪，缺的是候选队列」。这一片闭的就是那一条 —— 并且
把那个守卫**删掉**：它命名的是一个已经闭合的缺口，留着它就是一句再也不会有主人的话
（这条处置与 CHECKLOG I36 的「算了没人读」同族）。

§12 那句要落地的原话：

> `Backend.param_space()` 返回 `None` 的后端 = **代码型后端**，控制器自动切换成「LLM /
> 模板产出候选、bandit 只做局部精修」。

## 1. 一条主线：轮首取候选 → 跳过 Coder/Search → 回报记到**那个点**头上

| 位置 | 之前 | 现在 |
|---|---|---|
| 轮首（预算门之后） | 无 | `select_template_candidate(space, backend, caps, elem_bytes, bandit)`：剪枝 → bandit 排序 → **按顺位取第一个建得出来的点** |
| 取候选之后 | 无 | `bandit_arm` = 那个点的**去重键**（`template_arm`）；代码型轮仍是 tiling 三元组 |
| Step 3（拿代码） | Coder 生成 | `action="template"`，`current_code` = 实例化器交出来的源码 |
| L3 失败后的搜索 | LLM/邻域搜索 | 整条不走：`SearchAgent` 一次都不叫（下一轮的候选是轮首重取的，那时 bandit 已经吃过回报） |
| 血缘 | 无模板格 | `template_selection`（顺位/剪枝说明/被拒的点/选中点的 `as_lineage()`）+ `bandit_arm` |
| 全建不出来 | 无 | **停机**并说明（`template_no_candidate`），不退回代码型 |

**臂的位置是个撞出来的教训**：第一版把 `bandit_arm` 放在搜索块里算，而血缘条目在那一轮
**更早**的位置就 append 了 —— 于是产物里每一轮的臂都是 `None`（用例红了才看见）。臂必须在
append 之前有值。改到轮首算之后它与搜索块里用的是同一个值：搜索改的是**下一轮**的 sketch
与队列，都在算臂之后。同一件事的另一半：「这一轮有没有更新统计」不该由这一格回答 ——
那一格说的是「候选是谁」，有没有进账看 `metadata["bandit"].arms[arm]["pulls"]`。

## 2. 顺位取第一个**建得出来**的点（而不是「取第一个点」）

```python
ranked = bandit.order(pruned.kept, key=template_arm)   # 已有的排序器
for cand in ranked:
    try:  sel.chosen = instantiate_candidate(cand, backend, contract); break
    except Exception as exc:  sel.refusals.append((cand, f"{type(exc).__name__}: {exc}"))
```

- 实例化**惰性**：只建到第一个成功的点（真模板后端的实例化可能很贵），而**建不出来的点逐条
  留痕**；「某个点上实例化器一直失败」不该让这一轮没得跑，但它必须看得见。
- 排序方向由 `Bandit.order` 定死：**无观测的先试**（广度优先），有观测的按 UCB1 排。
  这里不另写一套、也不翻转它 —— 第一版我的注释写成了「有证据的排前面」，是**反的**，
  挂在用例上才发现（`test_unexplored_points_are_tried_before_explored_ones`）。
- 剪枝的输入是「每 SM smem 上界」，而它的载体以前只在 `agents._prune_by_smem` 里有一个私有
  `_Caps`。现在只有一处：`resource_check.caps_from_metrics(source)` + `MemCaps`
  （dict / `HardwareCaps` / 垃圾值三种输入一个口径；垃圾值 ⇒ `0` = **上界未知**，不是 1 KB）。

## 3. 停机理由：候选源枯了是一条**有名字**的边界

`ParamSpace` 按构造非空（校验过），所以 `chosen is None` 只剩一个含义：**所有点都建不出来**。
那时停在这里并说明（词汇表里加了 `template_no_candidate`），**不**退回代码型 —— §12 点名的
风险正是「把声明的参数空间悄悄丢掉后继续跑」。与 `search_error` 分开：那个是搜索抛异常，
这个是候选源枯了；复盘时一个看代码，一个看实例化器的报错。

   （观察面在那里），那条用例根本没被跑到。加宽目标集后同一条变异变红。**变异矩阵也要

   改成喂 `{"shared_mem_per_sm_kb": "abc"}` 才钉住那句话。

## 5. 明写没做到 / 仍然是纸面的

1. **没有真模板后端**：`select_template_candidate` 的实例化器、剪枝、排序都在链路上跑通了，
   但这是用一个**假模板后端 + 真 Python 核**（`SLOW_MATMUL`）证的 —— CUTLASS/TVM 的实例化器
   与其编译/测量路径**都还没有**。
2. **L1 的两道静态守卫仍是 Python 形状的**：`anticheat` 扫 `torch.matmul`、`interface_contract`
   找 `def kernel` 签名。模板源若是 C++/CUDA，它们**无法判断 ⇒ 倾向放行**（空转的守卫）。
   doc 73 就明写了这一条，这一片没有改变它 —— 但今天「模板源真的会被执行」已经是**通路上
   的事实**（不再只是宣称），所以这条比上一片更该尽快补。
3. **参数轴仍只有 tiling 三维有产出者**（`stages`/`warps`/向量宽度/`layout`/split-K 无人声明）；
   `prune_by_smem` 认不出三元组时**不剪**，所以少 `BLOCK_K` 的空间是不剪的（用例里踩到过）。
4. **§10.3 的 `score(c)` + ε-greedy + 分相预算**还没做：这一片的排序是「无观测先试 + UCB1」，
   探索系数固定 1.0，分相（explore/refine）没有实现。
5. **停止条件**：`template_no_candidate` 是新加的一条；「可靠停滞」的 K 轮判定与 roofline 收敛
   在本片没有改动。
6. **真机未复跑**：本机无 GPU；证据是 1858 条离线用例 + 14 处变异。
