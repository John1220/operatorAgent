# 三种预算与不可挪用的预留 —— §10.2 从「只有轮次数」到「有账本」

> 设计 §10.2 的表里，**真值 oracle 次数**被叫作「**真正的货币**」，最后 10% 的
> 「最终确认」预算写着「**不可挪用**……这条挡掉绝大多数『一次侥幸读数变成永久真理』」。
> 而代码里（修前）：这个数只被用来决定「该不该插一对参照核」，机时唯一的硬约束是
> **轮次数**，预留只以 opt-in 的 `require_double_confirm`（默认 `False`）存在 ——
> **默认配置下单次读数即可进长期记忆**。设计表里 §10.2 **连一行都没有**。

本篇记这一格怎么收口，以及**没做的部分**（分相、GPU 秒、任务级 wall clock）。

---

## 1. 账本：`operator_agent/budget.py`

`BudgetPlan`（限额）与 `BudgetLedger`（账本）分开：限额是任务级决定，账本是**一次运行**的
事实。三条通道互不相干：

| 通道 | 接口 | 判据 |
|---|---|---|
| 真值 oracle 次数 | `oracle_may(kind)` / `oracle_spend(kind)` | 非 confirm 只许花到 `总数 - 预留份额`；`confirm` 只许花自己那一格 |
| wall clock | `within_wall_clock(elapsed_s)` | 调用方传**已经过了多少秒**（账本不读钟：读钟会让它不可测） |
| LLM token | `tokens_exhausted(used)` / `note_llm_usage(used)` | 独立上限；超了 ⇒ 调用方退化成纯数值搜索 |

**「不可挪用」是本模块存在的唯一理由**，它的实现具体到两行：

```python
if kind == "confirm":                       # 预留只能花在自己的格子里
    return self.spent["confirm"] + n <= caps["confirm"]
return self.spent_all + n <= self.plan.oracle_total - caps["confirm"]   # 别处一律碰不到
```

### 切分顺序是判据的一部分（一个真被抓到的坑）

第一版按 `int(total * 份额)` 顺次切、**余数归 confirm**，于是预留**不单调**：

| total | calibration | explore | refine | confirm |
|---|---|---|---|---|
| 3 | 1 | 1 | 0 | **1** |
| 4 | 1 | 2 | 1 | **0** ← 3 次留得下、4 次反而留不下 |

那是纯粹的取整事故（`3-1-1-0` 有余额，`4-1-2-1` 恰好用光），不是设计意图。
改成**先切预留**、余数归 `refine`、次数不够时从低优先级收（先收标定的 1 次保底、再收
explore），于是：`total=1` 全留给预留，`total=2` 是 1 explore + 1 confirm，
`total≥3` 起预留恒 ≥ 1，`total=100` 恰好是 5/55/30/10。**账目恒等式 `sum(份额) == total`
有 300 个取值的用例钉住**（1..300 全覆盖）。

## 2. 四处接线（判据算了没人读，是这个仓最常见的失效方式）

| # | 位置 | 做了什么 |
|---|---|---|
| 1 | 轮次**最前面**（`conductor.py` 循环开头） | 两道 fail-closed 的门：墙钟到点 / oracle 次数用尽 ⇒ 各自一条停因并 `break`。位置是判据的一部分：放在 Coder/Planner 之后就变成「先花完写代码的钱，再说这次测量买不起」 |
| 2 | 测量点（与 `_true_measurements` **同点**） | 记账。一个地方决定「什么算一次真值测量」⇒ 不可能「花了没记」或「记两次」 |
| 3 | 心跳（§10.2 的 5% 预检标定） | **只记账、不被拦**，超支由 `calibration_over_plan` 报警 |
| 4 | token 超预算 | `perf_data["llm_budget_exhausted"]` ⇒ SearchAgent 走 `_rule_optimize`（纯数值搜索）而不是 `_llm_optimize` |

第 3 条是刻意的取向：**让预算饿死标定，等于把「尺子有没有坏」变成一件可以因为缺钱而跳过
的事** —— 与 §10.5-5（agent 不能编辑自己的尺子）同一族。所以那一格只有账，没有闸门。

第 4 条没有新增方法签名：走 `perf_data`（与上一片的 `tuning_refused` 同一条通道），
`SearchAgent.run` 见到信号就跳过 LLM。注意它**不是**「LLM 不在」那条路 —— 那条路会
`raise`（规则模板已不再是缺 LLM 时的替补），而这是「LLM 在，但这一轮额度花完了」。

停因是两条**新词汇**（`wall_clock_exhausted` / `budget_exhausted`），与 `rounds_exhausted`
分开记：复盘时一个要调轮次上限，一个要调预算或缩小任务。

## 3. 守卫与变异（8 处，每处都真跑过变红）

| 变异（把判据改回坏的样子） | 变红的用例 |
|---|---|
| 撤掉轮次开头的 oracle 门 | `test_measurements_stop_at_the_total_minus_the_reserve` |
| 测量点不记账 | 上一条 + 预留那条（共 3 红）——**这是写用例时抓出的实现缺口** |
| 非 confirm 可以碰预留 | 同上 |
| `confirm` 不再专属（与非 confirm 同规则） | `test_confirm_can_still_spend_after_explore_is_refused` |
| 补测不记账（预留没有消费者） | `test_the_reserve_is_spent_by_the_final_confirmation` |
| 墙钟边界改 `<=` | `test_wall_clock_is_strict_and_records_the_last_check` |
| token 永不判超 | `test_over_budget_never_asks_the_llm_for_a_structural_change`（共 4 红） |
| **标定格用完就不跑心跳** | `test_heartbeats_keep_running_after_the_calibration_share_is_used_up` |

最后一条的**第一版变异写法本身不成立**（我写成「拦总数」而不是「拦标定格」，于是它在
测试里根本没生效、全绿）—— 换成真实坏实现才红。**变异不变红时先怀疑变异，别急着加守卫。**

实现缺口那一行也值得单独记：门读了账本，却**没人在测量发生时记账** ⇒ 门永远不响、
预算等于没接。那是这个仓最常见失效方式（判据算了没人读）的**镜像**：闸门装了、账没记。

## 4. 明写的边界

* **`explore` / `refine` 今天不分相**。设计给了 55/30 的切分，可分相需要「参数搜索是不是
  平台化了」这条判据（§10.3 的升级门，CHECKLOG **I53**，零实现）⇒ 今天被强制执行的只有
  「总数 - 预留」与「预留专属 confirm」两条；`phase_caps` 是**计划**（有读者：产物快照与
  用例），循环只花 `explore` 一格。
* **三种预算默认全关**（`BudgetPlan()` 三个 `None`）。默认生效的机时承诺会改变每一次真机
  运行的行为，而「本轮要不要花这次钱」是任务级的决定 —— 与 `require_double_confirm`
  同一处置。没设上限时账本仍落盘（`plan` 里明写三个 `None`），不假装拦过。
* **按 GPU 秒的预算未做**。今天只有**次数**。设计 §10.3 的
  `score = P(beats_best) × 预期增益 / 预期 GPU 秒` 要的是秒，而秒的口径要先把「一次测量
  在哪种形态下花多少秒」量出来（远端有墙钟、本地 MockGPU 没有）——留给它自己一片。
* **任务级 wall clock 从哪来未定**：`TaskSchema` 里没有这个字段，今天只能由调用方在构造
  `Conductor` 时给。设计说它是「任务级」的硬上限。
* **真机未复跑**：这一片全在离线假 GPU 上验（本机无卡、`LLM_API_KEY` 未设）。能声称的是
  「判据与接线有产物且变异能红」，不是「真机上的机时账已经准了」。
* 轮次级别的门只在**开新的一轮**之前拦；一轮**内部**的多次花费（候选决赛的 L1/L2、
  心跳、修复轮）不走这个门 —— 它们不吃 L3 读数。若将来出现「一轮里多次真值测量」的路径，
  记账点要跟着扩（`_true_measurements` 同点扩，不另立第二个计数）。
