## 一、吸纳的是什么，凭什么信

C2 来自 harness 工程一系的调研结论（doc 20 第三节，判定 ✅ 采纳）：**上下文分两层，热层放「本轮要动手的东西」，冷层放历史；并且禁止递归摘要**。依据是两条一手实验数字 —— 摘要会毁掉约 60% 的事实、级联摘要再侵蚀约 54% 的操作性约束，而模型自信度不变（也就是说它不会发现自己被削过）。

我方对应的问题陈述当时是猜的：「prompt 逐轮堆积 sketch/代码」。这份文档干的第一件事就是**把猜测换成数字**。

---

## 二、先量：负担在哪一行

`benchmarks/measure_prompt_layers.py` 用真实代码路径构造 prompt（`SearchAgent` 推进 sketch 版本 → `CoderAgent._llm_generate_code` 渲染），LLM 只是个收信人，所以不需要 GPU、不需要模型，曲线完全由生产代码决定。

改动前，6 轮：

| 路径 | prompt 字符 v1→v6 | 增幅 | hint 块占 prompt | 每条 hint 在 prompt 里出现次数 |
|---|---|---|---|---|
| SearchAgent LLM 路径（每轮不同 hint） | 11001 → 11703 | **+6.4%** | 3.1% | **2** |
| SearchAgent 规则回退路径（每轮同文案 hint） | 11001 → 12897 | **+17.2%** | 7.0% | 2、4、6、8、**20** |

三个数字纠正了三条猜测：

1. **代码不堆积**。`current_code` 是覆盖式的，Fixer 每轮只拿一份 `code=code` —— 我原先以为「逐轮代码历史」是主要负担，它根本不存在。
2. **堆积的只有 `sketch.optimization_hints` 一处**：两处 append 都是 `旧 + 新`（`agents.py` 的 LLM 与规则路径各一处），而 `current_sketch` 每轮被替换，于是日志一路无界增长。规则回退路径更糟：它每轮生成**同文案** hint，6 轮后 26 条里绝大部分是同一句。
3. **最贵的其实不是历史，是重复注入**。sketch 的 JSON 与模板的 `{{optimization_hints}}` 是同一份列表的两个注入点，所以**每条 hint 一律出现 2 次**，冷层叠上去之后到 20 次。这个跟"逐轮"无关，第 1 轮就在付。

绝对量级要说清楚：基线 prompt 有 11 KB（大头是 SKILL），所以最坏情况是 +17%。**这不是一场火**，但重复注入是白付的，堆积方向是错的，两者都便宜到没理由不修。

## 三、改了什么（四处，都不引入压缩器）

| 位置 | 改动 |
|---|---|
| `schemas.py` `UnifiedSketch` | 新增 `hints_this_version`（热层）。`optimization_hints` 语义收窄为**冷层累计日志**，仍进 `to_dict()` 与快照，谁也不丢数据 |
| `schemas.py` `hot_hints()` | 返回热层；**v1 还没有「本轮」概念，退回全量日志** —— 写反了会让第一轮生成完全看不到设计建议，这是这层设计真正的风险点 |
| `schemas.py` `to_prompt_dict()` | 渲染进 prompt 的 sketch **不带任何 hint**：hint 在 prompt 里只留 `{{optimization_hints}}` 一个通道 |
| `agents.py` `_hint_log()` | 冷层日志去重保序；顺带 `_clean()` 挡掉 LLM JSON 里的非字符串（一个 dict 混进来会以 Python repr 印进 prompt） |
| `agents.py` / `coder_pipeline.py` | 两条 coder 渲染路径都改走 `hot_hints()` + `to_prompt_dict()` |

**没有做摘要/压缩**，按 C2 的证据这是刻意的：冷层不进 prompt 就够了，不需要有人替它写摘要。`SearchAgent` 的 prompt 仍带全量 `to_dict()`（它的模板没有独立 hint 块，JSON 是唯一通道）—— 那是本轮明确不动的部分，见第五节。

## 四、改完的曲线

```
----- SearchAgent LLM 路径 -----        ----- SearchAgent 规则回退路径 -----
v1  冷1 热1  prompt 10946  每支出现[1]   v1  冷1 热1  prompt 10946  每支出现[1]
v3  冷3 热1  prompt 10993  [1]           v3  冷7 热5  prompt 11104  [1]
v6  冷6 热1  prompt 10995  [1]           v6  冷8 热5  prompt 11104  [1]
    → 6 轮 +0.4%                             → 6 轮 +1.4%
```

- 每条热 hint 出现次数从 `2`（最坏 20）变成 **1**。
- 规模曲线在第一次优化之后就**压平**：v3→v6 每轮增幅 ≤2 字符（那是 `block_n` 数字本身在变），不再是每轮 +140 / +370。
- 规则路径的冷层从 26 条降到 8 条（去重），且不再进 prompt。
- 全量单测 324 passed / 4 failed（新增 11 条守卫；那 4 个是长期红，早于本段），`tests/golden_regression.py compare` 4/4 PASS 无功能回归。

## 五、守卫与变异

`tests/test_prompt_layers.py`，11 个用例。核心是三条行为断言：热层每条恰好一次、**冷层专有句子出现 0 次**、规模曲线后半段每轮增幅 < 30 字符。另加两条静态守卫：`agents.py` 里读 `sketch.optimization_hints` 的函数**只能是 `_hint_log`**（AST 扫描，新加 coder 路径直接读冷层就红）、两条 coder 路径都必须经 `hot_hints()`。

变异 8 条，逐个注入 `operator_agent/` 后跑守卫（一次性脚本，不入库；先 `compile()` 再跑，并强制清 `__pycache__` 与 macOS 的 `~/Library/Caches/com.apple.python`，同时断言变异必须改变文件尺寸 —— 这三招都是为了堵「读到变异前的字节码」这种假绿）：

| # | 变异 | 抓到它的用例 |
|---|---|---|
| K1 | Coder 退回渲染冷层 | 5 条同时红（含规模曲线） |
| K2 | sketch JSON 带回冷层（双注入点复活） | 单次性 + 冷层专有 + 规模 |
| K3 | 冷层不去重 | `test_cold_log_dedupes...` |
| K4 | `hot_hints()` 去掉 v1 回退 | `test_hot_layer_falls_back...` + 非空转检查 |
| K5 | pipeline 路径退回冷层 | `test_pipeline_coder_path_is_hot_too` |
| K6 | `_clean` 不再过滤非字符串 | `test_non_string_hints_never_reach_the_prompt` |
| K7 | 反序列化丢掉热层 | `test_round_trip_keeps_both_layers...` |
| K8 | `to_prompt_dict` 不删热层 | 单次性 + round-trip |

K5 第一版**只被文本守卫抓到**（`hot_hints()` 字样还在另一处），补了 `CoderPipeline._sample_one` 的行为用例之后才算真被量到 —— 文本守卫能挡「忘了改」，挡不住「改错了」。

## 七、这份改动没证伪什么，以及两个未修

- **没证明「少给历史能让模型写得更好」**。要判那个得拿真实的「修 N 轮仍失败」case 做 A/B，而本次效应量是 1 KB 级、基线 prompt 11 KB，按 doc 35 的教训，那种 A/B 设计在这个量级上没有判别力。这里成立的是「白付的重复不该付」+「冷层不该伪装成现状」，不涉及模型质量。
- **`SearchAgent` 的 prompt 仍然带着完整冷层**（`to_dict()`）。它没被这次改动覆盖，因为它的模板没有独立 hint 块，动它要先决定「hint 走 JSON 还是走专门块」。规则回退路径去重之后，那里的负担已经从 26 条降到 8 条，所以不着急。
- **未修（记账）**：`conductor.py:713-717` 每轮把 LLM 账单 `summary()`（含按 caller 分解的 `prompt_tokens`）写进 `artifact.metadata`，而 `ArtifactStore.save()` **根本不序列化 metadata** —— `output/*/result.json` 里没有它。于是「上下文有没有再次膨胀」在生产跑完的产物里是看不见的，这次的曲线只能靠离线渲染脚本量。属于本项目反复出现的「算了没人读」同类，修法是保存时带上，但那是另一主题，不混进本提交。
