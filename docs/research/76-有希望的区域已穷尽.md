# 有希望的区域已穷尽：停滞出口的另一半（CHECKLOG I64 / Stage 3 第四片）

设计 §10.4 的那一行有两个条件：

```
| **可靠停滞** | K 轮 valid 无改善，且**有希望的区域已穷尽** | 必须"穷尽"才算, 不能只因轮数 |
```

第一半早就有实现（`max_stagnant_rounds=2`），**第二半在代码里不存在** —— 于是循环在
「轮数够了」的那一刻就宣布停滞。而设计恰好在备注里点名了这种读法是错的，理由也在下面那一行
写着：**「无法再改进」这个结论本身必须可信**。这一片补的就是那个结论的第二半。

## 1. 三态，而不是布尔

`operator_agent/exhaustion.py` 只回答一个问题：**候选空间被覆盖了吗？**

| 状态 | 含义 | 后果 |
|---|---|---|
| `exhausted` | 有一个**可枚举**的候选全集，且每个点都至少观测过一次（`total`/`tried`/`untried` 一起记） | 与 K 轮无改善同时成立 ⇒ **停**，停机理由点名两半 |
| `unexplored` | 可枚举，但还有没试过的（附标签） | **不停**；「达到阈值却没停」记进 `declined` |
| `unknown` | **无法确立**：候选空间由 LLM/规则按需产生，没有可列举的全集 | 停滞条件**不成立**，收口交给 `max_optimize_rounds` 与 §10.2 的预算 |

为什么不是布尔：这个仓已经反复记过「缺 ≠ 0」被压成一个位的代价（`exclusive=None`、
`external_load=None`、`shared_mem_per_sm_kb=0` 都是同一族）。这里被压掉的那一位会让
**整个优化的终止条件**变成一个不成立的结论 —— 而这正是设计那句「最难的部分」的所指。
`Coverage.exhausted` 是三态属性（`True`/`False`/`None`），并且有一条用例专门钉住
`None` **不许**被读成任何一边（变异 M2/M3 各钉一边）。

**空集不算已穷尽**：一个空的候选列表会让每一轮都满足「已穷尽」，是最危险的那种自证
（「空队列 ⇒ 可以停」）。所以 `candidates is None or len == 0` 返回 `unexplored` 并记
`total=0`，调用方自己决定这种状态意味着什么（M1 钉住）。

## 2. 位置与「后填」：这一轮的血缘在轮首就 append 了

覆盖判定要等**本轮的观测进账**（这一轮的候选试过没有）才算得出来，而血缘条目在轮首就
append 了 —— 这个文件里同一个坑已经踩过两次（`bandit_arm`、`_round_selection`）。第三次的
处置沿用仓里已有的形状：**存一个会被后填的字典**（与 `permanent_effects` 同一写法），
于是「这一轮的覆盖判定」在产物里不会是一串 `null`：

```python
_coverage_record: dict = {}          # 轮首: 血缘里存的是这个对象的引用
...
_coverage_record.update(_coverage.as_dict(), threshold_reached=_threshold)   # 判定处后填
```

`threshold_reached` 与状态一起落，是因为「没停」有两种完全不同的原因，而复盘要能分开：
**没到阈值**（还在攒证据）与**到了阈值但没穷尽/无法确立**（我们不认为停滞成立）。
`CoverageLedger.declined` 只数后者（M6 钉住「没到阈值的不许计进 declined」）。

## 3. 两条接线

| 位置 | 之前 | 现在 |
|---|---|---|
| 模板型轮首 | 只有剪枝结果 | `template_points` 的结果同时作为**候选全集**（`assess_coverage(_universe.kept, …)`，`universe=template_space`） |
| 代码型轮 | — | `undeclared(FROM_LLM_ON_DEMAND, "候选由 LLM/规则按需产生")` —— 恒为 `unknown` |
| 停滞出口 | `rounds_without_improvement >= max` ⇒ 停 | `… >= max` **且** `coverage.exhausted` ⇒ 停；否则打印/记账后继续 |
| 血缘 | — | `coverage`（后填字典：状态/全集来源/试过几个/没试的是谁/是否到阈值） |
| 产物 | — | `artifact.metadata["coverage"]` = `{rounds, declined, last}` |

**一个语义变化必须明写**：代码型路径**不再**因为「轮数够了」提前终止。这是设计要求的
（「不能只因轮数」），代价是平坦区会多烧几轮 —— 有界性靠 `max_optimize_rounds` 与
§10.2 的三种预算，而且 §10.3 的结构升级门在那片平坦区里本来就有产出路径（门通过 ⇒
停滞计数清零、把结构改动交给 LLM）。三条断言这条变化的用例都改了**观察面**而不是放宽：
`test_conductor_stagnation` 那条拆成「不停 + 留痕」两条，`test_measurement_validity` 与
`test_l3_provenance` 里原来拿「提前终止」当代理的两条改成断言**达到阈值**与**没有拒评**
（它们本来要对照的就不是「停在第几轮」）。真停滞仍能终止的保护移到**可判**的模板型路径
（`tests/test_exhaustion.py::TestExhaustedRegionStillTerminates`：剪枝只剩一个点时，
第 3 轮两个条件同时成立 ⇒ `stagnant`）。

## 4. 为什么代码型路径今天恒为 `unknown`

不是「暂时没接」。要判「代码型路径的区域穷尽了吗」，得先有「什么算可枚举的候选空间」这个
定义：LLM 每轮可以提出新邻居、甚至换结构（那正是 §10.3 三条件门管的事），而规则路径的
±1 邻域格是**围着当前 sketch 转的** —— 换一个 sketch 就有新的一步邻域，覆盖不是单调的，
所以「已穷尽」在今天的形状下**不成立**。写成 `unknown` 是把这件事说清楚；写成 `exhausted`
会让停滞重新变成「只因轮数」，写成 `unexplored` 则是假装还有希望（两者都错）。

⚠️ 一个容易写反的地方（M10 钉住）：`assess_coverage(None, …)` 是 `unexplored`（空集不算
穷尽），所以代码型路径**必须**走 `undeclared(...)` 而不是「传 None 给同一个判据」。
第一版就是那样写的 —— 那会让代码型路径拿到 `unexplored`，语义上等于「还有候选」，
虽然结果同样是「不停」，但记录里那句话是错的。

## 6. 边界（➖/⏳）

- ➖ **代码型路径没有覆盖判据的生产者**：它需要「什么算可枚举的候选空间」的定义。今天
  这一路径的收口是轮次上限 + §10.2 预算（多烧几轮平坦区是**设计要求**的代价，不是漏做）。
- ➖ **模板型的可判性依赖剪枝**：`template_space` 的全集是**剪枝后**的点。剪枝只估单缓冲、
  按每 SM smem 上界判 —— 上界未知时（`MemCaps(0)`）不剪，全集变大，「已穷尽」更难成立
  （方向是**保守**的：更难宣布停滞，而不是更容易）。
- ⏳ **没有真模板后端**：这一片的端到端只在假模板后端（`_FlatTemplateBackend`）上跑过。
- ➖ **`unexplored` 不改变搜索动作**：它只拒绝「宣布停滞」，不会把没试过的候选**优先**
  排进下一轮 —— 那是 §10.3 选择器的事（`ε` 那一支），两处的分工今天靠约定而不是靠类型。
- ➖ 真机未复跑（本机无 GPU）：三态与两条接线只在 Mock/假后端的读数上验证过。
