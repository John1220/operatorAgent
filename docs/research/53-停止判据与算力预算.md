## 一、问题

D 片要把 `_perf_weight` 的排序轴从「绝对性能数」换成「离这台卡的可达上界还有多远」
（`kernel_db.py:25-45` 的 docstring 已把这行欠账指向 doc 49 §八 第 14 条）。它前面排着两个
前提：① `KernelRecord` 里得有 `bound_type` 的**写者**；② 分母得是按 shape 索引的曲线
（C 片 / doc 51 §五）。

调研这一圈要回答的是另一个问题，也是 D 片的另一半：**在什么条件下判定「这个核不值得再花
轮次」**。我们今天的三个出口都是我自己拍的数，没有任何外部对照：
`max_optimize_rounds=3`（`conductor.py:162`）、`max_stagnant_rounds=2`（`:346`）、
`ROOFLINE_CONVERGED_PCT = 90.0`（`measurement.py:109`）。

## 二、一手取证：哪些句子站得住

### AutoKernel（arXiv 2603.21331）—— 与我方三个出口同形的四条判据

抓 `https://arxiv.org/html/2603.21331`：237,301 字节 → 去标签 43,615 字符。逐字命中
（引号内是原文，含它自己的 LaTeX 残留 `2 × \times`）：

> It transitions to the next kernel when: (1) 5 consecutive reverts, (2) 90% of GPU peak
> reached, (3) 2 hours elapsed, or (4) 2 × \times speedup achieved.

这句落在**公式 (1) 之后、`4 Five-Stage Correctness Verification` 之前**（即第 3 节末，
不是 subagent 标的 §3.4 —— 它的章节解析系统性偏移，行号/节号一律以我这次定位为准）。
配套的四条判据分类在贡献列表里写作：

> An Amdahl's-law orchestrator with explicit move-on criteria (plateau detection,
> peak utilization, time budget, speedup threshold).

keep 规则（Algorithm 1，逐步）：

> 6: if pass ∧ t′ > 1.01 ⋅ t_best then 7: k_best ← k′; t_best ← t′; n_rev ← 0 { keep }

plateau 的经验量纲（这条是我们最缺的东西 —— 不是阈值而是**分布**）：

> Plateau : After 30 to 50 experiments, consecutive reverts increase as the kernel
> approaches hardware limits. The orchestrator triggers move-on.

跨算子的分配轴是 Amdahl 提速公式，f 是该核占总 GPU 时间的比例、s 是拿到的加速比：

> S = 1 / ((1 − f) + f / s)   (1)

反面教材式的一句话，正好是本仓「先观测后判定」的外部同调：

> write a candidate, benchmark it, keep improvements, discard regressions, repeat.

### KernelBand（arXiv 2511.18868v2，11 Feb 2026）—— 每轮把预算给哪个配方

抓 `https://arxiv.org/html/2511.18868`：436,440 字节 → 去标签 87,032 字符。站得住的：

> We formulate this as a contextual bandit problem rather than full Reinforcement Learning
> (RL) for three key reasons: first, optimization trajectories are short, making immediate
> reward predictive of final performance; second, LLM generation variance complicates
> long-horizon value estimation; and third, bandits offer rigorous regret bounds under our
> structural assumptions, ensuring sample efficiency.

选择规则是**带掩码的两项 UCB**（原文 `Masked UCB`，只在 `M_{i,s}=1` 的合法动作里取
`argmax (μ̂_{i,s} + c·ln t / N_{i,s})`，即 (簇, 配方) 对上的经验均值 + 探索项）。
平均遗憾界 (7) 与终式确实存在（`B.4 Final Average Regret Bound`，
`R(T) ≤ O(√(K|S|T log T)) + LεT`）。

测量协议那句对本仓有直接可比性：

> The function performs 100ms of warmup runs to stabilize GPU state, followed by 1000ms of
> timed runs. We report the median execution time to reduce sensitivity to outliers.

聚合口径（**这一条与 doc 51 D5 那场「聚合口径看不见 186 倍污染」的争论直接对撞**）：

> Speedup = Σ_i t_baseline,i / Σ_i t_optimized,i
> … shapes with longer execution times naturally dominate the aggregation.

它明说了长耗时 shape 天然主导 ⇒ 这是**总时间比**而非逐 shape 中位比。我们逐块比值序列
（doc 46/#37）走的正是它的反面，且我们有过被聚合口径掩盖的实际事故。

消融那条是本仓判据方向最强的一条外部背书：

> replacing our bandit policy with LLM semantic reasoning regresses performance to 0.97×
> (below the reference kernel), validating that learned execution statistics outperform intuition.

**学到的执行统计 < 换成模型直觉 ⇒ 掉到参考核以下（0.97×）**。我们的 D 片正是把排序轴从
「抄来的先验数」换成「这台卡上的测量数」，这条是同一个方向上的已发表反例。

预算常数：`T = 20` 为默认、`T = 40` 用于收敛性分析（§4.3.1）。headline 是
`up to 1.91× geometric mean speedup`。

## 三、转述里**不成立**的三条（不得引用）

subagent 报告把下面三条写成带节号的原文引用。我在 43 万字节里逐字搜过，全部**不存在**：

| 转述 | 我的检索结果 |
|---|---|
| `r_t = 1 − T(k_{t+1},H)/T(k_t,H) ∈ (−∞,1]`（标 §3.1） | `T(k` 命中 **0**；`reward is defined` / `speedup as the reward` 均 0。原文只在遗憾界 (7) 里以 `r_t` 记奖励，**没有给出这个闭式** |
| `UCB = 均值 + √(2 ln t / n) + α·ψ(s,φ(k))` 三项、且 `α ≥ 0`（标 §4.3-ish） | `α` 命中 **0**、`bias term` 0。原文 UCB 是**两项**（`μ̂ + c·ln t/N`）；`ψ(s,φ(k))` 这个词**存在**，但身份是「profiling 算出的 compatibility」，不是加权进 UCB 的第三项 |
| cold-start：「前 3\|S\| 轮每个 (簇,策略) 对至少拉一次，且这些拉取不计入遗憾分析」 | `cold`、`at least once`、`excluded from the regret` 全部 0 命中 |

三条的处置：**都不写进 D 片的依据**。第二条尤其危险 —— 我本来打算把「profiling 偏置项」
借成「配方先验按可达性打折」，这正是那条不存在的公式唯一支持的形状；如果照抄转述，
D 片就会把一条我自己编的机制标成外部一手。
⇒ 通则（本仓第 N 次撞上）：**转述里的节号与闭式一律自己取原始字节核；
搜不到时先怀疑检索面，再下「不存在」的结论** —— 为此我把 `α|\\alpha`、`ψ|\\psi`、
`at least once`、`cold[- ]start` 都放宽重跑过一遍（§二 里那些「确实存在」的句子是这么定出来的）。

## 四、我方现状对照（先核「是不是已经做了」）

| 判据形状 | AutoKernel | 我方今天 | 差在哪 |
|---|---|---|---|
| 平台期（连退 N 次） | 5 consecutive reverts，量纲是**几百次实验**，plateau 在 30–50 次之后才出现 | `max_stagnant_rounds=2`（`conductor.py:346`），量纲是 **3 轮** | 阈值形状我们有；**它的 5 是配在 30–50 次的预算上的**，我们的 2 配在 3 轮上。这两个数不可互相照抄 |
| 贴上界 | 90% of GPU peak | `ROOFLINE_CONVERGED_PCT = 90.0`（`measurement.py:109`） | **撞数**。我们的门还多两层它没有的前置（`measurement_can_gate is False`、`peak_trusted is not True` ⇒ 直接不判收敛，`measurement.py:172-179`）—— 它的 90% 是分母可信才成立的东西，它文中没写这件事 |
| 时间/算力预算 | 2 hours elapsed（单核） | **只有轮次上限，没有时间或 token 预算** | 这是真的缺口：我们的成本闸是 `max_optimize_rounds`，一轮里烧多少 token、多少秒没有出口 |
| 达成加速比目标 | 2× speedup achieved 就 move on | `speedup` 落进血缘 (#53 修过 None 口径)，但**不作为出口** | 刻意：把「目标倍率」当出口要求一个可信的分母，正是缺口 1/3 在管的事 |
| 跨算子分配 | Amdahl 公式 (1) 给 f 与 s ⇒ 排序优化次序 | 单任务单算子，无跨算子层 | 结构差异，不是缺陷。等有多算子任务时才可谈 |

## 五、吸纳 / 改造 / 拒绝

1. **吸纳（改造后）**：把「时间/算力预算」做成**第四个出口**，形状照 AutoKernel 的四分法，
   但**判据落在我们能测的量上**：轮次、墙钟秒、`llm_cost` 三个口径各自设上限，
   并且——关键差异——**预算触顶时不判「已收敛」，判「未判定就停了」**。
   它的 `2 hours elapsed` 与 `90% peak` 是同一级的「move on」，对我们不行：我们已经被
   「把像样的值塞进失败里」和「缺证据当否定证据」这两族坑过（doc 49 §7.14、#53），
   预算触顶必须写成独立的 `stopped_reason="budget"` 而不是复用 `converged`，
   否则下一轮检索会把「没钱了」当成「这个核到顶了」学进去。
   **这条的先决条件本轮核完，答案基本为负、但我第一版数错了**：`conductor.py:926` 写
   `artifact.metadata["llm_cost"] = cost_summary`，而 `artifact_store.py:71-74` 的注释明写
   「`metadata` 整个不进 `result.json` (llm_cost 也一样只在内存里)」⇒ **每次生产运行的
   `result.json` 里没有成本**。
   ⚠️ 第一版这里写的是「全仓 `cost_summary` 只有两行、读者数 0」—— 那是拿**手里那个局部
   变量名**去 grep 的结果。按接口上的键名 `llm_cost` 重数，读者有两处：`harness_pass_rate.py:176`
   的 `cost_from_metadata()` 与 `golden_regression.py:357`，两处读的都是**同一次调用链里的内存
   对象**（后者再把两列抄进 `tests/golden_registry.json` —— 那是 golden 路径自己的出口，
   不是运行产物）。所以缺的是**跨运行**那一半，不是「没人读」。两种说法要修的东西不同：
   前者补一个顶层键就够，后者会让人去动那两个本来就工作的读者。已挂号 CHECKLOG I6。
   同族先例就在紧挨着它下面：环境指纹与 `resume_status` 都因为「读者在下一次运行里」
   被单独立键落盘（`artifact_store.py:75-80`）。
   ⇒ 第四出口的第一个动作不是加判据，是把 `llm_cost` 按同样方式挪过落盘边界，并配一条
   「从 `result.json` 读回来」的探针（doc 49 §7.16 的教训：判据算出的东西要立刻写一个
   从产物读回的探针，单测读内存对象看不见落盘边界）。没有跨运行的成本读数就没有成本出口。

   **【2026-09-29 已落码 `aaa2632`】** 上面那个「挪过落盘边界」做了，而且**只做了观测**：
   `artifact_store.py` 单独立 `llm_cost` 顶层键、缺账单时不写这个键、只搬这一个键不倒整包
   `metadata`（里面放着含真实路径的执行快照外挂）；`tests/test_cost_persistence.py` 6 例，含
   「从 `result.json` 读回」的探针与写侧/读侧键名的 AST 契约，变异标定 6 条 0 逃逸。
   **没有加阈值、没有加出口** —— 阈值仍等 #48 的散布。

   ⚠️ **但同一轮里我把口径说满了**（`2de05dc` 才补上）：#70 接的是 `cost_tracker.summary()`，
   而账本挂在 client 上**累加**、`reset()` 全仓没人调 ⇒ 一个 client 跑第二个任务时落盘的
   是**累计值**，不是「本次运行」。这个失效本仓量化过一次
   （`harness_pass_rate.run_one`：六次运行的 token 排成 15638→…→166345 的累计曲线被当
   独立样本求和，总量高估 **3.25 倍**）。按累计值判停 = 第二个任务一开局就背着第一个任务
   的账单被提前判穷。现在写侧取 `summary_since(watermark())`，并随值落
   `scope="this_run"` 与 `process_total_calls` 两个口径标注；用例是「同一个 llm 对象跑两次」
   （`tests/test_iteration_lineage.py::TestCostScopeIsPerRun`，含「两次之和等于账本总量」
   这个绝对锚点），变异标定 6 条 0 逃逸。已挂号 **CHECKLOG I7**。
   ⇒ 通则：**值过了落盘边界 ≠ 口径是对的**；补读者那一轮就要同时问「它统计的是哪一段时间」。
2. **不吸纳**：`5` / `30–50` / `2 hours` / `T=20` 这些**常数**。它们与我们差两个数量级的预算
   （3 轮 vs 几百次实验），照抄等于把别人的采样密度当自己的阈值。这与 doc 16 那条
   「各家步数上限不吸纳」是同一个决定，这轮只是给了它一个量化的理由。
3. **不吸纳**：bandit 本身（UCB /  regret 界 / 簇)。我们要的不是「哪个配方值得多试」这一层,
   而是「值不值得再花一轮」; 上 bandit 需要先有 (簇, 配方) 的重复拉取统计,
   而循环是**串行单候选**（`conductor.py:484` `action = "generate" if round_num == 1
   else "optimize"`，一轮一个候选）、`max_optimize_rounds=3` ⇒ 样本量撑不起任何臂的均值。
   这条不是拒绝思想而是拒绝**顺序**：等 #48 量具第二轮把 rounds-to-pass 的散布测出来再说。
4. **改造**：`Speedup = Σt_base/Σt_opt` 这个总时间比是 KernelBand 的 headline 口径，
   **不 adopt**，但值得当**对照**跑：doc 51 D5 已经量到聚合口径能藏住 186 倍污染，
   两个口径并列打印比换掉任一个都安全（「并排两数分母不同源」这条陷阱的处置方式是标出口径，
   不是选一个）。
5. **待 D 片**：`_perf_weight` 换达成率。这一圈调研**没有**改变 D 片的形状，只是多了一条
   外部反例背书（§二 的 0.97× 消融）。前提①②仍然排在前面。
