# 真机复跑：H20×8（2026-10-02）

## 前置纠正

此前我在卡点表与 doc 76/77/78 的边界里反复写「真机未复跑（本机无 GPU）」，并在答复里说过
「没有那台服务器的可达性/凭据」。后半句是**我没查就下的判断** —— `~/.ssh/config` 里的
`algorithm-h20` 一直是可用的，实测：

```
$ ssh algorithm-h20 'hostname; nvidia-smi -L | head -2'
algorithm-ykd4wefe-0000
GPU 0: NVIDIA H20 (UUID: GPU-e4f8f9cd-...)
（共 8 张 H20, python3.10.12 / triton 3.7.1 / torch 2.13.0+cu130 / ~/.local/bin/uv 0.12.17）
```

这正是本仓那条纪律的实例：**本机没卡 ≠ 远端不可用** —— 缺证据不是否定证据。

## 跑法

`Verifier` 直连 `RemoteExecutor(mode="ssh")`（不经 LLM），核用仓里语料里的
`kernel_db._TRITON_MATMUL_CODE`（`tl.dot` 改为 `input_precision="ieee"`），
4096³ fp32 matmul，两组实验：`verify()` 与 `verify_l3_only(static_guards=False)`。
脚本 `/tmp/real_machine_smoke2.py`，整轮 L1+L2+L3 23.6s（SSH + uv + triton JIT + 基准）。

## 两个**新**观察（真机独有，本机复不出来）

1. **语料里的「已知好核」在 H20 上过不了 fp32 的 L2**：`_TRITON_MATMUL_CODE` 原样跑
   （`tl.dot` 默认精度 = TF32）⇒ `max_abs=7.92e-04`, `matched_ratio 0.44` vs 容差 1e-4，
   L2 FAILED。改成 `input_precision="ieee"` ⇒ `max_error=0.0` 通过。注意任务里写的
   `ConstraintSpec.max_error=1e-2` **没有**放宽 L2 —— L2 容差按精度档（`tolerance` 表）
   而不是按任务声明。⇒ 「语料里的核是不是能直接当起点」这件事，在真机上有一个反例。
2. **租约的 `external_load=0.0` 与选卡时的读数不是一回事**：harness 打印
   「卡与 7 个其他进程共享, 瞬时 util=0%」，而同一次 L3 载荷里的
   `external_load=0.0` / `competition=clean`。两者**不必**矛盾（选卡是测量前的快照、
   载荷是测量窗内的采样），但产物里没有一格把这两个时刻分开 ⇒ 读者可能把它读成
   「同一时刻两个说法」。按本仓纪律这属于**观察**，处置要另开一片（不是这一跑的任务）。

## 边界（这一跑**没有**覆盖的）

- ➖ **模板型端到端**：没有真模板后端，参数轴实例化/候选队列/覆盖判据仍只在假后端上跑过。
- ➖ **非 Python 源**：没有任何后端能执行 C++/CUDA 模板源 ⇒ I65 的三态在真机上仍只在
  Python/Triton 那一侧被观察到。
- ➖ **多卡**：只用了 1 张卡（GPU 2），`interference_domain` 未观测、`lease_waves` 无消费者、
  异构分区/多卡算子仍无生产者。
- ➖ **LLM 路径**：这一跑刻意不经 LLM（无 `LLM_API_KEY` 依赖），所以 prompt/生成侧没动。
- ➖ **`stages` 剪枝**：剪枝是控制端代理，真机复跑对它没有增量证据（它需要的是真 smem 上界
  与文本覆盖口径，那仍是 §12 的下一片）。
- ⏳ 单次真机读数：没有重复跑，`dispersion 0.01` 只是这一次的离散度。
