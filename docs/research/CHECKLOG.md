> 形制借自 LeetCUDA `kernels/interview/book/CHECKLOG.md`：分类 + 证据 + 状态，
> **冻结源不回写**（原文留着，错在这里挂号）。
>
> 为什么要这份：本仓已被「论文说 vs 仓库做」坑过至少四次（Ecdysis / AdaExplore /

> 1. **原话**（或极短摘录）+ 出处（文件:行 / URL / commit）

> 3. **后果**（不改会怎样；已修的写修在哪）
> 4. **类别**：`C` claim 宣传/论文 · `I` implementation 代码与文档不符 ·
>    `M` math 公式/口径 · `P` performance 性能数字 · `S` stale 过期注释 ·

### I5 · 一条已提交用例的判定随控制机装不装 torch 翻转
- **原话**：`test_absent_external_reference_still_uses_builtin` 断言没有外挂参考时
  参考侧是 `pytorch_eager`
- **实证**：`operator_agent/verifier.py:1099` 在 `import torch` 成功时返回 `pytorch_eager`，
  `:1102` 的 except 分支返回 `numpy_reference`；这台控制机
  `importlib.util.find_spec('torch') is None` ⇒ 本机**稳定红**，装了 torch 的机器稳定绿
- **出处**：doc 52 §五；doc 49 §八 第 20 条；commit `ac2f497`
- **后果**：两层。① 这条用例绿不绿说明的是这台机器的依赖表，不是代码对不对 ——
  与「非确定性期望值不许写死」同族，新形态是依赖 availability 而非随机数，
  所以它**不会偶发**，会在一类机器上恒红、另一类上恒绿；
  ② 它照出的生产语义更该担心：L2 的参考在没有 torch 的机器上**静默换成 NumPy**
  （没有 TF32/fp16 那条路径），「L2 通过」的对比对象跟着控制机变 ——
  缺口 5 那四道门全在管后端与分母，**参考侧没有门**
- **2026-09-30 追加的读数**：这台控制机上其实**有两套解释器**，而这族缺陷在单机上就能翻转 —— 同一份 HEAD `00a88ed` 的干净 worktree，`~/opt/miniconda3/bin/python3`（3.9.12，torch 2.8.0）读是 **986 passed / 1 skipped**，`/usr/bin/python3`（3.9.6，无 torch）读是 **981 passed / 1 failed / 5 skipped**，**总数都是 987**、差的 5 条全在这一族，零行代码不同。本仓此前所有「带 1 条红」的读数都是后者，而 `python3` 这个名字解析到哪一套取决于当时的 `PATH`（Bash 每次调用都是新 shell）。
- **类别**：I/S · **状态**：⚠️ 已知，未修（`verifier.py` 等是并发会话的在途文件）

### I54 · §10.2 的「真值 oracle 次数」（设计说它才是**真正的货币**）没有预算语义；预留只是 opt-in

- **原话**：设计 §10.2 —— 「| **真值 oracle 次数**（GPU 测量次数）| **真正的货币** |
  5% 预检标定 / 55% 探索 / 30% 精修 / **10% 最终确认** |」以及「最后 10% 的"最终确认"
  预算**不可挪用**：任何要写进长期记忆或对外报出的结论，必须留有**一次独立重测**的预算。
  这条挡掉绝大多数"一次侥幸读数变成永久真理"。」
- **实证**：全仓只有**轮次数**（`max_optimize_rounds` / `max_stagnant_rounds`）与
  `CostTracker`（`llm_client.py:166`，生产读者只有落盘账单那一处 `conductor.py:1500`）——
  「真值测量次数」这个货币**没有任何预算语义**：`_true_measurements`（`conductor.py:306`）
  只服务心跳节奏（`_heartbeat_for_next_measurement`）。没有 wall clock 预算；没有 token
  超预算之后「退化成纯数值搜索」的那个模式；预留只以 opt-in 的 `require_double_confirm`
  （默认 `False`）存在 ⇒ **默认配置下单次读数即可进长期记忆**。设计表里 §10.2 **连一行都没有**。
- **出处**：`docs/design/autonomous-operator-agent-design.md` §10.2（设计表里它**连一行都没有**）、
  `operator_agent/llm_client.py:166`（`CostTracker`）、`operator_agent/conductor.py:306,1500`
  （`_true_measurements` 只服务心跳节奏 / 账单只用于落盘）、`conductor.py:1617`
  （预留可写者只有 opt-in 的 `require_double_confirm`）
- **后果**：修前那一格的具体形状是「设计与实现各说一套」—— 设计把**真值测量次数**叫作
  「真正的货币」，而代码里这个数只被用来决定「该不该插一对参照核」；机时唯一的硬约束是
  **轮次数**，而一轮的机时开销并不固定（重测、心跳、候选决赛都改这个比例）⇒ 想省机时的人
  只能去调轮次数，那个旋钮与「花多少次测量」根本不是一回事。预留那一半更直接：默认配置下
  **单次读数即可进长期记忆**，而设计说那条预留挡的是「一次侥幸读数变成永久真理」。
- **修法**：新增 `operator_agent/budget.py`（`BudgetPlan` 限额 + `BudgetLedger` 账本），
  四处接线 —— ① 轮次**最前面**两道门：墙钟到点 / oracle 次数用尽，各自一条停因
  （`wall_clock_exhausted` / `budget_exhausted`，与 `rounds_exhausted` 分开），fail-closed
  在**开机时之前**；② 测量点的记账与 `_true_measurements` **同点**（一个地方决定「什么算
  一次真值测量」）；③ 心跳（§10.2 的 5% 预检标定）只记账、**不被拦**，超支由
  `calibration_over_plan` 报警 —— 让预算饿死标定等于把「尺子有没有坏」变成缺钱就能跳过的
  事（§10.5-5 同族）；④ token 超预算 ⇒ `perf_data["llm_budget_exhausted"]` ⇒ SearchAgent
  走规则路径（`_rule_optimize`）而不是 `_llm_optimize`。账本落 `artifact.metadata["budget"]`。
- **预留的实现（本条的要点）**：「不可挪用」= 非 confirm 的开销一律只许花到
  `总数 - 预留份额`，而 `confirm` 只能花自己那一格；份额切分**先切预留**、余数归 refine
  （顺序不能反：余数归 confirm 会让预留**不单调** —— 试过 total=3 有 1 次而 total=4 是 0 次，
  那是取整事故不是设计意图），四格之和恒等于总数的账目恒等式有用例钉住。
- **守卫**：24 条用例（`tests/test_budget.py` 16 条纯账本 + `tests/test_budget_gate.py`
  8 条走真 `Conductor.execute`）+ **8 处变异全红**（撤 oracle 门 / 测量点不记账 / 非 confirm
  可碰预留 / confirm 不再专属 / 补测不记账 / 墙钟边界改 `<=` / token 永不判超 / 标定格用完
  就不跑心跳 —— 最后这处的第一版变异写法本身不成立（它拦的是总数不是标定格），换成真实
  坏实现才红，一并记下）。写用例时抓出的实现缺口：门读了账本却**没人在测量点记账** ⇒
  门永远不响（这正是「判据算了没人读」的镜像：闸门装了、账没记）。
- **边界明写**：`explore` / `refine` **今天不分相**（那需要 §10.3 的「平台化」判据，见 I53）
  ⇒ 被强制执行的只有「总数 - 预留」与「预留专属 confirm」两条，`phase_caps` 是**计划**
  （有读者：产物快照与用例），循环只花 `explore` 一格；三种预算**默认全关**（opt-in，与
  `require_double_confirm` 同一处置）；墙钟只量「这一次运行」（构造时建账本、每次 `execute`
  新建）；按 GPU **秒**的预算（设计 §10.3 的 `score` 公式要它）**未做** —— 今天只有次数；
  任务级 wall clock 从哪来（`TaskSchema` 里没有这个字段）**未定**。
- **类别**：I · **状态**：✅ 2026-10-02（次数/墙钟/token 三条接上；分相与 GPU 秒仍是 ⏳）
  → 见 [doc 67](../research/67-三种预算与不可挪用的预留.md)

### I46 · §14-8「关掉心跳该窗口不写记忆」在生产路径上没生效
- **原话**：设计 §14.8 表格第 8 行 —— 「关掉心跳 | 该窗口观测全部不可用, **不写记忆**」；
  状态表把它记成 ✅（`calibration` 的判定 + oracle 的规则 2 与「到期没跑」）
- **实证**：2026-10-01 真机 H20 (`benchmarks/smoke_spine_h20.py` 走**生产** L3 入口)：
  同一次测量写出的 metrics 里并排出现

  那次真机没写进语料，只是因为加速比 0.42x 被 `persist_decision` **另一道门**偶然挡住了
  （拒因原文: `相对同机基线没有加速 (speedup=0.4155)`）—— 换一条跑得赢的读数就会进去。
  已修：发布值改为收口点的答案（`metrics["eligibility"] = obs.eligibility.as_dict()`），
  本地推导删掉，只有「收口点没跑成」那条 fail-closed 的 all-False 保底
- **出处**：`docs/research/63-*.md`（真机冒烟，run1 = 修前证据）；`operator_agent/verifier.py`
  `_assess_measurement`；`tests/test_stage1_acceptance.py::test_published_eligibility_is_the_closure_points_answer`
  （**对旧代码变红**）
- **后果**：读「已检查」而护栏不生效 —— 与 P1-4「声明了没人派发」同族：这次是**算了、发布了、
  但发布的是另一份**。同族条目 I45（判据零调用者）、I47（检查无喂给者）
- **类别**：I · **状态**：✅ 已修（发布值 = 收口点答案 + 生产 L3 级别的守卫）

### I47 · `pairing_conflict` 跨卡检查在生产路径上没有喂给者
- **原话**：设计 §11-2 / §13.4 硬性语义 2 —— 「A 卡基线 vs B 卡候选的『加速比』直接作废」；

- **后果**：这条检查今天只在离线用例里活着；真机正确性靠「一次调用一张卡」，一旦有人把
  两次调用的读数拼成一个加速比（缓存基线 / 分轮拼接），没有任何东西会作废它
- **修法**（2026-10-01）：远端**按臂**采身份（`_arm_identity`：`visible_index` + 卡名 +

  那件事，而背后没有任何观测（全仓只有一个测试在读它）。现在它由观测算出三态：

  规则 3 同族；两处读同一对标签，所以不可能分叉）。拒评时**发布的档位也换成收口点的答案**
  （否则又是 I46 的形状：`measurement_validity=valid` 与 `eligibility` 全 False 并排）。

- **类别**：I · **状态**：✅ 同卡那半已修（2026-10-01，`tests/test_pairing_observation.py`

### I48 · 远端运行时盾的证据不落地（`lib_fallback` 对唯一需要它的那条路径恒 False）
- **原话**：spine-review P1-4 —— 「反作弊命中必须把 `lib_fallback` 写进 metrics，否则资格

- **出处**：`docs/research/63-*.md`；`operator_agent/anticheat.py`（`lib_fallback_from_error`）、
  `operator_agent/verifier.py` 远端 L2 失败分支
- **后果**：资格规则 4 恰是给「静态审计漏了、盾拦住了」准备的，而对这条路径恒 False ⇒
  又一次「算了、没人读」。已修：错误文本按**自家文案常量**认领（不做模糊匹配，否则任何含
  `matmul` 的报错都会被读成库回退），符号进 `lib_fallback_evidence` 的 `runtime:` 段
- **类别**：I · **状态**：✅ 已修（+ 正反两条用例；摘掉喂给 → 对应用例变红）

## 使用约定

1. **检索侧**（Designer/Coder/Search/Fixer）注入 prompt 时，只取 `状态=⚠️` 且与当前
   kernel_type/硬件相关的条目；`🚫` 与 `✅` 不进 prompt（已闭环的不是教训是历史）。
2. **新立条**必须四件套齐全；证据栏不写「据某某说」。
3. **不回写冻结源**：论文/上游文档保持原样，错在这里挂号并给出我们自己的口径。
4. 与 `FailureDatabase` 的分工：那边记**我们跑出来的失败**，这边记**别人文档里
   的假话与我们自己的过期注释**。
