# 50 · 断点续跑的完整性：半个快照、被扔掉的轮次，与「请求了续跑」这句谎

日期 2026-09-29。主题：`execution_snapshot.json` 这条**唯一**的续跑链路，在写侧与读侧各有
一处静默降级，按 task_id 搜索快照的那条分支还有两处更静的错。全部本地可复现，不占 H20 机时。

选题理由先说清楚，免得被读成「顺手清理」：#48/#54/#57 三条都要机时与选卡，用户还没批，
所以这一轮的目标是挑一条**完全能离线验证**的链路做完外部吸纳 + 落地。选中续跑链路是因为
它同时满足三件事：每轮都在写、代价以「LLM 轮次」计、而它的失效方式恰好是本仓反复出现的那一族
（**降级不响**）。取证撞出来的东西比选题大。

## 一、本仓实况（三处，全部实测过，不读代码猜）

取证脚本在 `/tmp` 跑（一次性，不入库），走真 `MockGPU` + 真 `Conductor.execute` + 真
`ArtifactStore` 落盘 —— 不用声明式假件当被测对象（doc 48 §6.5 那条纪律）。

### 1.1 半个快照会让一次续跑多烧 3 次 LLM 调用，而产物里查不到

| 场景 | LLM 调用 | stdout | 产物里有没有痕迹 |
|---|---|---|---|
| 健康快照续跑 | **1** | 「🔄 断点续跑」 | — |
| 快照被截一半后续跑 | **4** | 「⚠️ 快照加载失败，改为从头开始」 | **没有** |

机制是两半凑成的：写侧 `conductor.py` 原来是

```python
with open(path, "w", encoding="utf-8") as f:      # ← 这个 open 当场把文件截成 0 字节
    json.dump(snap, f, ...)
```

`open(...,"w")` 的截断发生在**序列化之前**，所以「写到一半进程没了」留下的不是上一个可用版本，
而是一份截断 JSON。读侧则把**任何**异常吞成一行 print 后从头跑。两边各自都「有道理」，合起来的
后果是：**续跑请求被降级成重跑，而不留任何记录** —— stdout 不归档，事后复盘看到的只是一次
跑得比较久的运行。

### 1.2 按 task_id 找快照时，永远选中**旧**的那个

`_resolve_snapshot_path` 的第三条分支是 `os.walk("output")` 里**第一个** task_id 命中的文件。
两个候选（`aaa_run_round1` 与 `zzz_run_round3`）实测：

```
创建顺序 先1后3 → 选中 run_older_round1 (round_done=1)
创建顺序 先3后1 → 选中 run_older_round1 (round_done=1)
```

两种创建顺序都选中 round_done=1，即 walk 顺序既不是时间序也没人规定过，而它替用户决定了
「从第几轮接着跑」。后果是**把已完成的轮次扔掉重来**，与 1.1 是同一件事的另一个入口。
顺带：同一条分支里 `except Exception: pass` 会**静默跳过**读不动的候选 —— 「找不到」与
「找到了三个、其中两个是坏的」在旧实现里是同一个返回值 `None`。

### 1.3 那条分支不认 `OPERATOR_AGENT_OUTPUT_DIR`

搜索根写死成 CWD 相对的 `"output"`，而产物根目录是 `ArtifactStore` 按环境变量算的。实测：
快照在 env 指向的目录里 → 返回 `None`（静默从头跑）；再在 CWD 造一个 `output/` 的诱饵
（`round_done=7`）→ 它被选中，**读的是本次配置根本没写过的目录**。同一个缺陷的两种后果：
要么丢续跑，要么捡到别的运行的状态。`_flush_snapshot` 里第 1 轮的 staging 目录也写死
`"output"`，于是设了重定向的运行会把快照落进仓库的 `output/` —— 那个变量存在的全部理由
就是别让旁路产物混进真实语料（doc 43 第三节量的正是这件事）。

## 二、外部一手依据（每条自己 curl 重取并 grep 原文；承重的都标 ✅）

| # | 出处 | 原文 | 对本设计的意义 |
|---|---|---|---|
| ① | Python 官方 `os` 文档，`os.rename` | "If successful, the renaming will be an atomic operation (this is a POSIX requirement)." ✅ | 原子性由 POSIX 保证，不是 CPython 的额外承诺 |
| ② | 同上，`os.replace` | "The operation may fail if src and dst are on different filesystems." ✅ | 临时文件必须**同目录** —— 这条把「tmp 放哪」变成了约束而不是风格 |

| ④ | 同上 | "If newpath exists but the operation fails for some reason, rename() guarantees to leave an instance of newpath in place." ✅ | 失败也保留旧版本 —— 这正是 1.1 缺的那一半 |

| ⑦ | 同上 | "When it's time to continue the Workflow, Temporal doesn't restore memory from a snapshot. It starts the Workflow code from the beginning, replays the Event History…" ✅ | 「快照续跑」与「事件溯源」是两种不同的架构选择，明说自己选了后者中的浅那一档 |
| ⑧ | Stripe API 文档 | "if a connection error occurs, you can safely repeat the request without risk of creating a second object or performing the update twice." ✅ | 幂等的条件是**有一个键**；本仓 `cx-{task_id}:{签名}` 那条内容派生 id 是同族做法（doc 45/49） |

## 三、改了什么（四处，全在 `conductor.py` / `artifact_store.py` / `schemas.py`）

1. **原子写**：`snap = tmp` → `flush` → `os.replace(tmp, path)`，`finally` 清残留 tmp。
   同目录（依据 ②）。效果：读者只会看到「旧完整版」或「新完整版」。
2. **续跑结局落盘成状态**：`KernelArtifact.resume_status`，五态
   `not_requested / no_snapshot / resumed / unreadable_snapshot / task_mismatch`，带
   `root`、`candidates`、`unreadable`、`reason`（**只存异常类名**，`str(e)` 可能带路径而
   `result.json` 会被搬走）、`size_bytes`、`round_restored`。
   ⚠️ 刻意**不**塞进 `artifact.metadata`：`artifact_store.py:73` 的注释明写 `metadata` 整个
   不进 `result.json` —— 挂在那儿就是下一份「算了没人读」（doc 49 §7.9 那条教训的复用）。
   落盘之后立刻补一条「从产物里读回来」的断言（同一条纪律）。
3. **搜索根跟着配置**：`_resolve_snapshot_path` 改成实例方法，根 = `self.store.output_dir`，
   与真正写产物的那个对象同源（不在第二处重读环境变量 —— 本仓有过「同一个键两个值」）。
   同时返回 `scan` 账目，于是 `no_snapshot` 能说清是「一个都没看到」还是「看到 3 个、2 个读不动」。
4. **多候选取最新可解析的那个**：key = `(round_done, mtime)`，并数出被跳过的坏候选。
   staging 目录也改用 `self.store.output_dir`。

## 四、吸纳 / 不吸纳（以及为什么这条边界画在这儿）

**吸纳**：上面四条。共同形状是「把不可能变成不可能」而不是「把日志写得详细些」——
①③④ 消除失效状态，② 让剩下的那个失效状态**必须**被记账。

**不吸纳（四条，都是主动拒绝，不是没做到）**：

⑤ **事件溯源 + 确定性重放（Temporal 那种，依据 ⑥⑦）**。它的代价是让主循环变成可重放的
   纯函数序列，而我们循环里的两个主要动作（LLM 采样、GPU 计时）都**不可重放** —— 真要照它做，
   等于把每次 LLM 响应与每次 L3 读数都记成事件并按事件恢复。那是另一套架构，而且它解决的问题
   （进程随时重启也要继续）比本仓的（崩溃后少烧几轮）贵一个量级。**本轮不建它**。
   留一条相邻的最小版本当候选：把「某轮的 LLM 响应」按 `(task_id, round)` 做键缓存，
   续跑时命中就不重发 —— 那才是 Stripe 那条幂等键（⑧）在本仓的正确落点。没做是因为
   **它需要真机长跑才能证明省下来的确实是钱**，而不是因为它难。
⑥ **`fsync` + 目录项 fsync（依据 ⑤）**。它防的是**掉电/内核崩溃**与 NFS；我们观察到并注入的是
   **进程级写失败**（`json.dump` 抛异常）。在没量过延迟、也不确定 `output/` 会不会被放到 NFS 之前，
   加 fsync 就是加一段没人测过的阻塞。记成欠账（第六节），不做成「看起来更严谨」。
⑦ **每 super-step 的更细检查点粒度**。本仓已经是每轮一写，粒度问题不存在；缺的是完整性，已修。
⑧ **把 `result.json` / `code.py` / `sketch.json` / `verify.json` / `benchmark.json` 一起改成原子写**。
   诱惑很大（同一个函数里五行），但**只有会被下一次运行读回来的那些**才需要这个保证。
   `result.json` 是这一档（它的读者是环境漂移自检的「上一次」扫描，`test_environment_drift.py:347`
   已经测过那条路读到坏文件时的行为），其余几个目前没有跨运行的读者。
   ⇒ 只把 `result.json` 记进欠账（第六节第 2 条），代码没动。一次改动铺满五处写，
   就是把「机制完整性」换成「看起来一致」。

## 五、验收

9 例新用例（`tests/test_resume_integrity.py`）：

| 用例 | 断言的形状 |
|---|---|
| 写到一半崩 | 旧快照仍完整可读、`round_done` 未变、没留 `.tmp` |
| 截断快照续跑 | 状态 = `unreadable_snapshot`、`reason` = `JSONDecodeError`、`size_bytes` 等于截断长度、**从 `result.json` 读回来** |
| 逐字节截断扫描 | 任何截断长度上「要么完整恢复、要么显式读不动」；补最后那一刀才测得到完整那份（这条用例第一轮就因为漏掉它而红） |
| 没请求 vs 找不到 | 两个不同状态，不许都写成「从头跑」 |
| task_id 不一致 | 独立状态 `task_mismatch`，并记下快照属于哪个 task |
| env 重定向 | 必须拿到配置里的那个（round 4），不许拿 CWD 诱饵（round 7）；`scan["root"]` 与实际写盘根同源 |
| 两个候选 | 取 `round_done` 大的那个，`candidates=2` |
| 坏候选 | `unreadable=1 / candidates=0`，不许静默消失 |
| staging 目录 | 落在配置根之下 |

**8 条变异注入全部变红，无逃逸**（M1 原子写退回报错、M2a 状态改名、M2b 不落盘、M3a 写死根、
M3b 不比轮次、M3c 不计数、M4 staging 绕开配置、M5 `result.json` 不写 resume）。
🔴 其中 M4 第一次跑歪了：替换文本里用了 `pathlib.Path` 而 `conductor.py` 没有 `import pathlib`，
于是变异靠 **NameError** 让 6 条用例变红 —— 看上去比真实覆盖更强。改成 `Path("output")`（语法有效）
之后恰好 1 条红，就是该红的那条。⇒ **变异标定本身要先标定**（第 4 次记这条），
判据是「红的那条是不是我以为让它红的那个机制」。

测试 713 → **722 passed / 0 failed / 3 skipped**（本片净 +9 例；读数取自**干净 worktree 的 HEAD**，
工作树此刻另有并发会话未提交的 28 条用例，在它上面读到的是 750，不是本片的数 ——
doc 49 §7.7 那条陷阱的第四次落地）。

## 六、还不能说什么 / 留下的账

1. **不能说「续跑从此可靠」**。本轮证明的是两件事：半个快照**不可能再出现**（①③④），
   以及读不动时**一定有记录**（②）。而「续跑跑完的结果 == 不中断跑完的结果」是更强的命题，
   它要求一次带真 LLM 的长跑中途被杀，再续跑对照 —— 需要机时与端点，记成 #48 那类需要批准的
   实验（新任务）。
2. **`result.json` 仍是非原子写**（第四节第 ⑧ 项）。它的读者是下一次运行的漂移自检，所以这条
   是真欠账而不是洁癖。修法和快照那条一样，但要先想清楚：`ArtifactStore.save` 一次写五个文件，
   原子性只在「读者按名字取那一个文件」时有意义。
3. **多进程并发写同一快照目录**没测过。跨进程锁保护的是 GPU 卡（`lock_identity()`），不是产物目录；
   两个进程同 task_id 同时跑本来就不该发生，但「不该发生」不是保证。
4. **NFS / 掉电场景**（依据 ⑤ 的 fsync 那条）明确不覆盖，等有机房证据再说。
5. 幂等键那条最小候选（缓存每轮 LLM 响应，键 = `(task_id, round)`）留在第五节 ⑤ 里没做，
   它才是本仓真正需要的「重放不重烧」。
