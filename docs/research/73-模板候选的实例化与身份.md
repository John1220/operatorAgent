# 模板候选的实例化：点 → 源码，身份不跟着代码走（CHECKLOG I61）

设计 §12 的那句话：

> 接入 TVM / CUTLASS 的最大风险是接口把"候选"硬编码成源码字符串——那一刻起，模板型
> 后端就无法接入，整条链路要重写。……`Backend.param_space()` 返回 `None` 的后端 =
> **代码型后端**，控制器自动切换成"LLM / 模板产出候选、bandit 只做局部精修"。

第一片（`beca5a0`，CHECKLOG I56）立了**联合类型 + 枚举 + 便宜代理剪枝 + 开关**，并且
把「声明了参数空间」这条路上的两处缺口都做成了 fail-closed。这一片补的是 §12 里被点名
「未实现」的那一步：**`TemplateCandidate` 的实例化（`build`）**。它同时把两处缺口的
归属分清了 —— 一片里最容易犯的错是把两个不同主人的缺口说成同一句「模板不支持」。

## 1. 协议词汇：`Instantiation`，以及一个与 `param_space` **刻意相反**的默认

```python
@dataclass(frozen=True)
class Instantiation:              # backend_caps.py
    source: str
    instantiator_ver: str = ""    # 自报版本; "" = 没自报 (三态里的「不知道」)
    evidence: str = ""            # 人读的出处 (模板名/参数/编译器版本)

class Backend:
    def param_space(self, contract=None):  return None      # 代码型: 有意义的答案
    def instantiate(self, template_id, params, contract=None):
        raise NotImplementedError(...)                      # 没有「默认实例化」这种东西
```

两个默认**方向相反**不是疏忽：`None` 在 `param_space` 那里是一个**有意义的答案**
（代码型后端），而实例化器**没有**「默认」可言 —— 静默返回一份空源码正是「把候选悄悄
当成源码字符串」的另一种写法。把方法立在基类上（而不是让调用方 `hasattr` 嗅探）是
`backend_caps` 开头第 1 条的理由：**静默 no-op 在这个设计下不可表达**。

## 2. 身份不跟着代码走

`BuiltCandidate` 是「点 + 它这一版构建出来的源码」：

| 问题 | 答案 | 为什么 |
|---|---|---|
| 两个**不同点**产出一模一样的源码，是一个候选吗？ | **不是**（`dedup_key` 委派给那个 `TemplateCandidate`） | §12 的全部要点就是「候选不是源码字符串」。碰巧同源的两个点仍然是两次不同的构建选择 |
| 同一个点被**两次**实例化（源码不同），是两个候选吗？ | **不是**（同一个点） | 身份是 `(template_id, instantiator_ver, 参数)`；源码变了只说明实例化器变了 |
| 那源码变化去哪了？ | `source_hash`（内容哈希，**跨语言**）+ `struct_sig`（Python AST 的 α-等价签名） | 前者对 C++/CUDA 源一样有效；后者只对 Python 源有效 —— 只记一个必然丢掉一半信息 |

`as_lineage()` 把两者作为**证据**发布（`build_source_hash` / `build_struct_sig`），
**不去替换** `struct_sig` 那个属于源码型候选的身份字段：两类候选的血缘字段不许互相冒名。
其中 `build_struct_sig == ""` 是三态里的「**量具不适用**」（C++ 源没有 Python AST），
不是「没有源码」—— 判读时别读成同一件事。

## 3. 五道守卫，与「为什么拒绝用异常」

`instantiate_candidate(cand, backend, contract)` 的每条拒绝都对应一种会被读错的状态：

| # | 判据 | 若没有它，会读成什么 |
|---|---|---|
| 1 | `is_template(cand)` 否则 `TypeError` | 源码候选溜进模板路径 ⇒ 去重口径与构建路径同时分叉 |
| 2 | 实例化器**可达**否则 `NotImplementedError`（点名后端与模板） | 「后端没有实例化器」被读成「实例化出一个候选」 |
| 3 | 返回值必须是 `Instantiation` | 返回值形状不定 ⇒ 下游各自解释 |
| 4 | 源码必须是非空 `str` | 「实例化失败」被读成「产出了一个空候选」，一路走到编译才发现 |
| 5 | `instantiator_ver` 自报且与参数空间里的版本一致 | 实例化器换了版本却不说 ⇒ 去重键把两个不同的构建读成同一个候选 |

**拒绝用异常**（而不是返回 `None`）：这五处都是**调用方或后端的错**，不是「这一轮没有
候选」这种可继续的状态。批量那一层 `instantiate_points()` 把单点异常收成
`InstantiationBatch.refusals`（带理由），于是整条链路上「N 个点建了 M 个」仍然看得见 ——
不塌成「这一轮有 M 个候选」。`empty_input` 与「建了 0 个」**分开记**（缺 ≠ 0）。

## 4. 两侧缺口分开说（本片最容易被合成一句话的地方）

```python
# conductor 里现在是这样调的:
refuse_unconsumed_space(
    require_supported_space(param_space_of(self.backend, task), self.backend),
    self.backend)
```

| 状态 | 谁拒绝 | 消息里能读到什么 |
|---|---|---|
| 没有参数空间 | 都不拒 | 代码型，照常走 LLM/邻域那条路 |
| 有空间、**没有实例化器** | `require_supported_space` | 「后端没实现 `Backend.instantiate`」——下一步动作是**后端**去实现 |
| 有空间、有实例化器 | `refuse_unconsumed_space` | 「点建得出源码了，但控制器的候选队列还没接上参数空间」——下一步动作在**控制器** |

把这两条合成一句「模板不支持」，两个完全不同的下一步动作就被同一句话盖住了。所以它们是
两个判据、两条消息，各自有主人。**实例化那一段（本片）不等于「模板这条路通了」**：
`refuse_unconsumed_space` 今天仍然拒绝，因为把建成的源码接进搜索循环要动候选队列的形状
（枚举 → bandit 排序 → 当成这一轮的候选），那是 Stage 3 的下一片。

## 5. 变异矩阵（12 处，全红）

| # | 变异 | 结果 |
|---|---|---|
| M1 | 身份跟着源码走（模板点当源码候选） | ✅ 红（4 条用例） |
| M2 | 版本不一致不再核对 | ✅ |
| M3 | 实例化器自报空就抹成空串 | ✅ |
| M4 | 空源码放行 | ✅ |
| M5 | 返回值形状不校验 | ✅ |
| M6 | 单点失败不再留痕 | ✅ |
| M7 | 空入参当成「建了 0 个」 | ✅ |
| M8 | 源码候选也能走这条路 | ✅（**第一次逃逸了**，见下） |
| M9 | 没有实例化器也放行 | ✅ |
| M10 | 控制器缺口不再拒绝 | ✅ |
| M11 | 可达性判据只认类覆写 | ✅（15 条用例） |
| M12 | 协议默认不再 raise（静默空实例化） | ✅ |

**M8 逃逸的那一次值得记**：我原来的用例写的是
`assertRaises(TypeError): instantiate_candidate(source_candidate(...))` —— 少传了 `backend`，
于是它抛的是「缺参数」的 `TypeError`，**类型那道判据一次都没被执行**。变异测试把这条
覆盖率漏洞照出来了（「变异不变红时先怀疑变异/用例覆盖面」）：用例改成喂一个**有实例化器**
的后端，让拒绝理由**只能是**类型，它才真的钉住判据本身。

## 6. 明写没做到 / 仍然是纸面的

1. **控制器还没有消费参数空间的候选队列**（`refuse_unconsumed_space` 仍拒绝）——
   枚举 → bandit 排序 → 把建成的源码当成这一轮的候选，是 Stage 3 的下一片。
2. **L1 的两道静态守卫是 Python 形状的**：`anticheat.static_audit` 扫的是源码里的
   `torch.matmul` 之类调用，`interface_contract` 找的是 Python 的 `def kernel` 签名。
   对 C++/CUDA 模板源，它们**无法判断 ⇒ 倾向放行**（空转的守卫）。今天没有「按后端声明
   分派第二套判据」这件事 —— 真接进模板后端之前必须补，写在这里免得把「过了 L1」读成
   「静态检查覆盖到了」。
3. **参数轴的产出者仍然只有 tiling 三维**：`stages` / `warps` / 向量宽度 / `layout` /
   split-K 还没有后端声明它们（第一片就明写了，本片没有改变）。
4. **没有真模板后端**：本片落的是协议 + 判据 + 用例（`Instantiation` / `instantiate` /
   `BuiltCandidate` / 批量留痕），CUTLASS/TVM 的实例化器与它们的编译/测量路径**都还没有**。
5. **真机未复跑**：本机无 GPU；全部证据是离线用例 + 12 处变异。
