## 一、吸纳的两条，以及为什么它们对本仓不是洁癖

`docs/defensive-patterns.md:27` — **Never hand untrusted output the ambient environment or
predictable paths**：

> Temp/spill files use a private (0700) dir, random names, and exclusive owner-only opens
> (`'wx'`, `0o600`) — predictable world-readable paths invite symlink races and disclosure.

`docs/defensive-patterns.md:19` — **Dispose must reach quiescence, not just request it**：

> A teardown that issues kills/aborts but returns before the work stops leaves orphans.

**判断（这一条是本文的核心，不是照抄）**：DSH 讲的是 disclosure 与 symlink race；对本仓更直接
的危害是**测量完整性**。原因在本仓的执行模型：探针驱动把 Python 脚本 scp 到那台 8 卡共享机
上**再执行它**，而原来两个驱动在被执行的那个名字上用的是固定名 ——
`verify_interleaved_ab.py` 的 `/tmp/_contender.py`（`:123-125` scp 到远端**同名**再执行）与
`verify_util_decontamination.py` 的 `/tmp/_util_probe.py`（`:296-300`，同样原名上远端）。
行号是 `git show ee29a5f^` 上逐条核过的。

⚠️ 一处**差点写过头**的边界：同文件里那份 `run_kernel_prev.py` 的 `/tmp`（`:120`）只是
**控制端**的写盘位置，它的远端落点是 `{runner_dir}/run_kernel_prev.py`（部署目录，不是
世界可写的 `/tmp`）。所以本片说「被替换风险」时数的是**两处**，不是三处 —— 第一稿把
`run_kernel_prev.py` 也算进「scp 上去执行的那个固定名」，那是凭印象扩了范围。

固定名的后果不是
别人读到我们的东西，而是：

```
我们写 /tmp/_contender.py  →  scp 到远端同名  →  ssh 执行它
                              ↑
                    这一秒里任何人都能替换这个路径上的文件
```

于是「干扰流」未必是我们写的那条，而**干扰流正是本仓花了两轮（doc 33/34）去消除的那个变量**。
一条公开路径能悄悄改掉我们的自变量，这比泄露严重。

拆除那一半的失效形态也不是「留个脏进程」：远端那条干扰命令自带跑到某个时间戳的自我期限
（默认 `+300` 秒），而**本地 `ssh` 客户端被 `terminate()` 不保证远端跟着停**。所以原来的
`interferer.terminate()` 之后直接返回，下一次跑在那张卡上的测量会在被抢卡的状态下被当成
安静读数——**我们自己就是 doc 34 里那个邻居**。

## 二、落地的形状

`benchmarks/_scratch.py`（新）四个函数，全部不碰 GPU：

| 函数 | 接住的失效 |
|---|---|
| `private_dir(prefix)` | 控制端目录：`mkdtemp` 的 0700 + 随机名，再走 `ensure_private` 显式核一次 |
| `ensure_private(dir, what)` | 权限带 group/other 位就 `raise`。**单独成函数是因为它在 `private_dir` 里处在死分支上**（见 §三 M3/M4） |
| `write_private(dir, name, text)` | `os.open(..., O_WRONLY\|O_CREAT\|O_EXCL, 0o600)`。不用 `Path.write_text` —— 它会**跟随已存在的符号链接**写进去，那正是 DSH 点名的形态 |
| `remote_scratch_path(name)` | `/tmp/<stem>-<secrets.token_hex(4)>.<ext>`。后缀来自 `secrets`，不是 pid（别的机器上会撞）也不是时间戳（可猜） |
| `stop_interferer(proc, run_remote, path, grace_s)` | 做到静默并**读回**证据，见下 |

`stop_interferer` 的四步与各自接住的东西，顺序承重：

1. `terminate()` → `wait(grace_s)`，超时才 `kill()` 再 `wait()` —— 只 `terminate()` 是「请求」而非「等到」（DSH `:19`）。
2. `pkill -f <唯一路径>` —— 本地 ssh 死了不等于远端进程死了；不显式收它，那条 +300s 的干扰流继续占卡。
3. `pgrep -f <唯一路径>` **读回**剩下的进程数。少了这步，第 2 步失败时函数返回的和成功时一样。
4. `rm -f` 收掉远端那份可执行文件。

第 2 步和第 1 片的 `remote_scratch_path` 是**互相成就**的：路径带随机后缀，`pkill -f` 才精确指得到
我们那一个，而不是别人的同名文件 —— 固定名上执行 `pkill -f /tmp/_contender.py` 会打死别人的进程。

两个驱动接上 helper，并在 `scp` 之后显式 `ssh … chmod 600`（`scp` 保留源 mode，但不许靠它）；
五个探针/测量驱动的 docstring 里那段「怎么跑」的说明，落点从 `/tmp/x.py` 改到家目录 `~/x.py`。

## 五、一条顺带撞出的、别人已提交的长期红

`tests/test_pluggable_reference.py::…::test_absent_external_reference_still_uses_builtin`
在 `ac2f497` 里被提交，本机**固定失败**：

```
AssertionError: 'pytorch_eager' != 'numpy_reference'
```

核过成因，不是并发写坏：`operator_agent/verifier.py:1099` 在 `import torch` 成功时返回
`pytorch_eager`，`:1102` 的 except 分支返回 `numpy_reference`，而这台控制机上
`importlib.util.find_spec('torch') is None`。也就是说——

1. **这条用例的判定随控制机装不装 torch 翻转**。属 doc 20 记过的「非确定性期望值不许写死」族，
   新形态是**依赖 availability 而非依赖随机数**：换一台机器它就换一个答案，绿不绿不说明代码对不对。
2. 更值得担心的是它照出来的生产语义：**L2 的参考实现在没有 torch 的机器上静默换成 NumPy**。
   `a @ b` 在 NumPy 里没有 TF32/fp16 那条路径，fp16 语义也不同，所以「L2 通过」这句话的含义
   跟着控制机变。这与缺口 5 那条「静默降级」同族，只是降级发生在**参考侧**而不是后端侧，
   而参考侧一旦降级，正确性判据整个换了对比对象。

本片**不动**它：`verifier.py`、`schemas.py`、`remote_executor.py`、`run_kernel*.py`、
`tests/backend_fakes.py`、`test_pluggable_reference.py` 都是并发会话的文件，纪律是不编辑、
不 stage。已作为 doc 49 §八 第 20 条记下，并挂号为 **CHECKLOG I5**，修法（用例侧显式标记 torch 可用性，生产侧降级要
留痕而不是静默换参考）留给那条工作的 owner 或工作树安静后另开一片。

## 七、不吸纳 / 边界

- **不用 `tempfile.NamedTemporaryFile`**：它给的是本地随机名，但我们需要的第二半是
  「远端名字也在执行前不可预测」，且 `NamedTemporaryFile` 的 `delete=True` 在 scp 之前就会
  让内容不在。手写 `write_private` 反而更短。
- **不引入 DSH 的 scrub-env 那半条**（丢弃 `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`）：
  本仓传给远端的是我们自己生成的脚本，不含用户代码，而凭据泄露的既有防线是脱敏审计 +
  `config.yaml` 已 gitignore。留在这儿是因为它**当前无失效面**，不是拒绝这条规则。
- **`_REMOTE_DIR` 仍是 `/tmp`**：那台机上只有它是公共可写区。DSH 那条规则要的不是「不用 /tmp」，
  是「路径不可预测 + 权限私有」，这两点都满足了。
- **`pkill -f` 按路径匹配是近似**：如果有人在命令行里echo了同一条路径，会被一起打死。
  共享机上这个概率远低于「固定名被替换」，且随机后缀把它压到可忽略；没有做 UID 过滤，
  因为 `pkill -u` 需要知道远端 UID，那又是一次探测。
