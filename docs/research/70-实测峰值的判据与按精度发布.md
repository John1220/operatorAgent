# 实测峰值的判据与按精度发布（设计 §13.5 / CHECKLOG I49 的下半格）

设计 §13.5 的原话是：

> **`probe_peak` 必须实测**：拿一个已知好 GEMM 打到真实峰值，而不是读 spec 表。
> 探测失败 → **roofline 收敛出口永久关闭**。

而本文要记的是这句话**落地时撞到的四件事**：①「实测」到底拿什么当样本（不能是另跑一个
benchmark）；②它是上界还是下界（下界，因此出口偏松——这条必须写进产物而不是写在注释里）；
③为什么必须**按精度**发布与读取；④为什么「失败了」也要落盘。以及本轮**没有**做到的
三件（跨运行、真机复跑、参考核自己没打到顶的残余风险）。

---

## 1. 改前的状态：出口在所有真机上关着，而这是设计要的方向

`measurement.roofline_converged` 只认 `peak_measured is True`（三态 fail-closed：
`None` / `False` / 表里来的都不算）。改前这个位由 `_theoretical_peak` 从
`HardwareCaps.measured_peak_tflops` 读，而全仓**没有任何写入者** ⇒ 真机 4096³ 的
Roofline 行里分母永远来自规格/推导表（H20 那行的出处自己写着「无公开官方页 + 算术推导」），
出口一律不开。

**关着不是缺陷**：关着只少一条停止条件（停滞 / 预算 / 不安全中止三条仍在），而开着会把
还能优化的核提前判成到顶。所以这一片的验收点不是「出口开了」，而是
**「标定这件事终于有判据、有产物、有读者，且失败时看得见理由」**。

## 2. 样本：同一次 L3 的**基线臂**，不是另跑一个 benchmark

「拿一个已知好 GEMM 打到真实峰值」有两种读法：

- 另起一次测量：多花 GPU 秒、多一份环境假设，而且它与**这一次**判停所依据的读数之间
  隔着时延（时钟/温度/占用率），正是「跨运行的环境漂移」那一族的近亲；
- 复用同一次 L3 调用里**已经付过钱**的那条基线臂：同机、同形状、同精度，读数与候选同批
  采集（block-interleaved + L2 flush），分母与分子来自同一个时刻。

本轮取后者。实测可达值 = `flops / baseline_time_ms`，其中 `flops` 就是 roofline 用的
**那一份**（`verifier._ai_numer_denom`，比值由 `_compute_arithmetic_intensity` 包装）。
为什么不另写一个「算 flops」的函数：那是第二个真源，而漂移的症状恰好是「探针的分母与
roofline 的分子不是同一个量」——两个数都长得像 FLOPS，日志里看不出来。

**成本是零** ⇒ 不占 §10.2 那 5% 的标定额度（那个额度留给心跳）。这不是省钱，是不重复测
同一个东西。

### 2.1 它是**下界**，不是器件极限（必须写进产物语义）

基线臂的实测可达值说的是「这台机器这个精度**至少**能跑这么快」。拿它当分母 ⇒ 利用率
偏大 ⇒ 收敛出口偏松。两条约束把风险压住：

1. **样本自己必须 compute-bound**（`ai >= ridge_point`）：访存受限的样本量的是带宽，
   不是 FLOPS；用它当分母会把「访存受限的快」误读成「算力接近到顶」。
2. **样本自己必须是 `valid` 档**：拿一个 degraded 的读数当分母，等于把「贴着上界了」建在
   一份自己都不可信的测量上。这与「roofline 收敛只认实测」是同一族纪律的下一层。

**残余风险明写**：如果参考核自己没打到顶（形状太小、调度差），出口仍会偏松。那时该修的
是参考核，**不是**放宽判据。这条风险今天没有被任何用例覆盖（本机无 GPU）——
它被记在这里，而不是被记成「已解决」。

## 3. 按精度发布与读取（一个键可以静默张冠李戴的地方）

同一张卡上 fp32 与 tf32 的分母差近一倍。只存一个标量，就必然有人拿另一个精度的数当分母，
而**日志里两者长得一模一样**（都是「peak=74.0 TFLOPS」）。所以：

- `HardwareCaps.measured_peak_tflops` 是 `{精度: TFLOPS}`（`None` = 从没探测过，
  *不是* `{}` —— 空字典会让读者以为「探测过、没结果」）；
- 键由 `peak_probe.precision_key_of` 从**这一轮选分母用的那个** `compute_used` 得到
  （`fp32_cuda_core→fp32`、`tf32_tensor_core→tf32`、`fp16/bf16` 类推），映射表只有一份；
- 读取取不到就当作**未实测**——不许借用别的精度，也不许回退成 FP32。

这条在用例里被钉成两条：`test_the_denominator_switches_to_the_measured_value`（换分母、
出处跟着分母走）与 `test_another_precisions_measurement_is_never_borrowed`（存了 fp16 的
实测值，这一轮分母是 tf32 ⇒ 仍然是未实测）。

## 4. 判据：七条拒绝，任何一条不过就不发布

`peak_probe.probe_peak(sample) -> PeakProbeDecision(measured, profile, refusals, detail)`
**从不返回裸 `None`**（交给下游解释必然有人解释成放行）。拒绝理由（各自单独可红）：

| # | 判据 | 拒绝理由（要点） |
|---|---|---|
| 1 | `real_device is True`（走 caps 声明的能力位） | 仿真读数可以驱动搜索，但不能当实测峰值 |
| 2 | 精度键可识别 | 分母按精度发布，认不出就不发布 |
| 3 | 有测量方法的出处 | 分不出「实测」与「抄表」的数不许进分母 |
| 4 | 有限正数 | `None`/`0`/负数/NaN/Inf/`True` 一律拒 |
| 5 | `validity == "valid"` | 探针自己也得过尺子的档位 |
| 6 | 离散度已知（三态） | 不知道稳不稳，就不拿它当分母 |
| 7 | `ai >= ridge_point` 且两者已知 | 没打到算力峰值 ⇒ 量的是带宽 |
| 8 | 不高于规格 `×1.05` | 采样买到的不是同一个量（稀疏/混精最常见） |

**关于第 6 条为什么不自设阈值**：测量侧早就给出了两个**结论**（`validity` 档位、
`dispersion_exceeded`）。这里再自己算一遍「离散度 > 5% 算不算大」就是同一个判定两处实现
（spine-review P1-6 的教训：`assessment.dispersion is not None and validity != VALID`
那个式子从不与任何阈值比较，只是把档位重编码了一遍）。所以探针只要求「离散度**被测过**」
（`validity == valid` 在没上报离散度时也可能成立 ⇒ 这一条**不**是空转），阈值判断留给
已经收口的那一处。

**第 8 条的存在理由**：规格不是上界，只是「同一个量」的对照。实测量高出 5% 以上最常见的
原因是稀疏/混合精度混入 ⇒ 那不是同一件事的数。没有规格可对照时不做这一条判断（其余六条
仍然要过）。

## 5. 失败也要留痕：「没标定」与「没接线」分得开

产物里永远写 `metrics["peak_probe"] = decision.as_dict()`（含 `refusals`），并且拒绝时在
Verifier 行里打印理由。这条是**实测抓到过**的那一类：本轮第一个版本的默认裁决没有读者，
于是「门关着」在产物里与「门没接上」长得一样，M10 变异因此存活。同理，探针的拒绝必须有
产物，否则「分母没换」永远有两种解释。

## 6. 本轮实测抓到的两个真接缝

1. **`_detect_theoretical_peak` 是缓存的，而发布发生在第 1 轮之后** ⇒ 第 2 轮读到的还是
   「没实测」，标定只在下一个进程里生效，而存放处明确**不跨进程** ⇒ 整条链在生产上等于
   没接。修法：缓存只留**表那一半**（设备身份与规格行是静态的），实测峰值那一半每次调用
   从存放处重读（`_refresh_measured_peak`，零成本、不重新探硬件）。
   *用例 `test_the_denominator_switches_to_the_measured_value` 正是这样抓到的。*
2. **`detect_hardware_caps` 有两个出口**（命中表 / 没命中表），只在末尾合并实测值 ⇒ H20
   这类**命中表**的卡永远读不到实测值——而它恰恰是最可能有实测值的那些。修法：一个
   `_with_measured_peak` 走两个出口。（这条也是先写错、再被冒烟测试打红才发现的。）

3. **「实测那一半的真源是存放处」这件事，连用例的注入方式都跟着变**：改前那批 roofline
   用例是把峰值 dict **预置进 `Verifier._theoretical_peak` 缓存**（那是「设备理论峰值是 X」
   的声明口）。加上 refresh 之后，这样预置实测值会在下一跳被存放处覆盖 ⇒ 用例红在「出口
   没开」，而机制其实是对的（**错的是注入位置**）。修法：用例改成走生产路径
   （`remember_measured_peak` 放进存放处，再让 refresh 读回去）——顺带把
   「存放处 → caps → roofline」这一整段也钉住了。这条值得单独记，因为它示范了一个通用
   形状：**只要一个量的真源换了地方，所有「手改下游快照」的用例都会以「机制坏了」的样子
   变红**，而它们真正的信息是「注入点过期了」。

三条都属于同一个母题：**「算出来了」与「接上了」是两件事**，而后者只有真跑一遍才知道。

## 7. 变异矩阵（本轮 11 处，全红）

| # | 变异 | 期望 | 结果 |
|---|---|---|---|
| M1 | `real_device` 那条不判 | 红线 | ✅ |
| M2 | 精度键认不出时按 fp32 发布 | 红线 | ✅ |
| M3 | 方法出处不判 | 红线 | ✅ |
| M4 | 非有限正数放行 | 红线 | ✅ |
| M5 | 探针自己的档位不判 | 红线 | ✅ |
| M6 | 离散度未知放行 | 红线 | ✅ |
| M7 | `ai < ridge` 放行（改成量带宽） | 红线 | ✅ |
| M8 | 高于规格 5% 放行 | 红线 | ✅ |
| M9 | 读取时**借用别的精度** | 红线 | ✅ |
| M10 | 存放处只在「没命中表」那一支合并 | 红线 | ✅ |
| M11 | 缓存那一半不重读（去掉 `_refresh_measured_peak`） | 红线 | ✅ |

M9/M10/M11 就是 §6 那三条接缝的「反向钉」——它们证明用例真的在钉接线，而不只是钉判据。

## 8. 明写没做到的三件

1. **不跨运行**：只在进程内生效，下一次运行重新标定（成本是零，所以「重标」不是浪费；
   落盘要等真机跑通再定——峰值带时钟/温度/占用率，把上次会话的数字留给下次会话正是
   「跨运行环境漂移」那一族）。
2. **真机未复跑**：本机无 GPU，全部证据来自离线用例；`MockGPU` 一律拒发（无
   `REAL_DEVICE`）这条**有**用例，但「H20 上真的标定出多少」今天没有观测。
3. **参考核自己没打到顶**的残余风险（§2.1）没有被任何量具覆盖。

另外，M9 那一族顺带暴露一件与设计文本的偏差：设计写的是
`probe_peak(device: DeviceKey) -> PeakProfile | None`，实现把它拆成
「装配（`sample_from_l3_metrics`）→ 判据（`probe_peak`）→ 发布
（`remember_measured_peak`）」，因为判据不该依赖采集方式，而「失败**不是** `None`」
这条要求本身就是对设计签名的一次修正（`None` 会被下游解释成放行）。
