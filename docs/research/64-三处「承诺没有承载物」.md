## 一、起点：一次「卡点盘查」抓到的三类缺口

上一轮的进度是：Stage 0/1/2 基本落地、真机 §14 冒烟零失败（doc 63）。于是把设计文档
逐条对着代码盘一遍，问的是同一个问题：**这条承诺有没有承载物？** 盘出来的东西分三类：

| 类别 | 例子 | 性质 |
|---|---|---|
| 承诺**没有实现物** | `probe_peak`（§13.5）、`Placement.lease`（§11）、`param_space`（§12） | 0 处实现 |
| 承诺**没有产物** | §17 第 3 件交付物「报告（含『我无法确立的事』）」 | 收集器有、产品没调用者、全仓没有报告文件 |
| 承诺**没有验收能判** | §19.4「在 §14 通过前不许声称资格审计带来收益」 | §14 八条只测它在不在岗，没一条测它在不在值 |

三件里挑了两件半做掉（`Placement.lease` 与 `param_space` 只在设计 §15 里明写成「没有
实现物」）：**峰值口径**（承诺被较弱的代理顶替，而顶替点正好是判停出口）、**报告产物**
（信誉所在的那一件缺席）、**§14-9 对照实验**（唯一能把中心主张变成可证伪的那一条）。

## 二、① 峰值实测 vs 口径核过（CHECKLOG I49）

**设计原话**（§13.5）：「`probe_peak` **必须实测**：拿一个已知好 GEMM 打到真实峰值，而
不是读 spec 表。探测失败 → **roofline 收敛出口永久关闭**。」

**代码做的事**：全仓 `probe_peak`/`PeakProfile` **0 处**；分母来自 `verifier._PEAK_BY_NAME`
（规格表 + 算术推导），而「可信」的判据是 `peak_trusted = 命中表行 且 出处串不以 ⚠️ 开头`
（`verifier.py:1383`）。H20 那行的出处是 `flash-attention dense 表 148/4.0 + 算术推导;
无公开官方页`（`verifier.py:91`）—— **不带 ⚠️ ⇒ trusted=True**，于是
`measurement.roofline_converged` 把收敛出口**开着**。真机 4096³ 的原文（doc 63）：

    [Verifier] Roofline: compute (AI=..., peak=74.0 TFLOPS (tf32_tensor_core|
    分母[h20] flash-attention dense 表 148/4.0 + 算术推导; 无公开官方页), ...)

这是一个**用较弱代理顶替较强要求**的例子，而顶替点正好是判停出口 —— 分母偏小会把还能
优化的核**提前**判成到顶（仓里早在 `_PEAK_SOURCE` 那段的注释里为 ⚠️ 行写过这条不对称代价）。

**修法**：把两问拆开，各自只有一个位。

| 问 | 位 | 谁写 | 谁读 |
|---|---|---|---|
| 表行**口径核过**没有（dense/sparse 没混、算术自洽） | `peak_trusted` | `verifier._PEAK_SOURCE` 的 ⚠️ 约定 | 达成率/轴证据（`optimization_planner`） |
| **真探测过**没有 | `peak_measured` | `HardwareCaps.measured_peak_tflops`（`None` = 从没探测） | **只有它**开收敛出口（`measurement.roofline_converged`） |

于是今天：**没有任何设备做过探测 ⇒ 收敛出口在所有真机上都是关的**，日志里明写
`⚠️未实测⇒收敛出口关闭`。这是设计要的方向，不是缺陷 —— 关着只是少一条停止条件
（停滞 / 预算 / 不安全中止三条仍在）。`probe_peak` 本体仍未实现，已写进设计 §15 的
「没有实现物」表。

**守卫成对**（`tests/test_measurement_validity.py`）：

- 口径核过但没实测 ⇒ 不开；实测过但口径未核 ⇒ 不开；两问都真 ⇒ 才开；老记录缺键 ⇒
  fail-closed（`test_roofline_converged_needs_a_measured_peak`）
- 这个位真的读 `HardwareCaps`，不是恒 False：给 `measured_peak_tflops` 一个值 ⇒ 翻真
  （`test_the_published_flag_reads_hardware_caps_not_the_peak_table`）
- 端到端：分母没实测时 `Conductor` 不宣布收敛（`test_conductor_stagnation`
  `test_unmeasured_peak_does_not_open_the_exit_either`）

## 三、② 报告产物（CHECKLOG I50）

**设计原话**（§17 第 3 件）：「**报告**：结论 + 证据链 + **"我无法确立的事"**（一等公民
章节）… 第 3 条的"无法确立"章节是自动跑系统的信誉所在。**一个从不说"我测不准"的自动
系统，它的所有数字都不可信。**」

**实际**：`confirm.UnableToEstablish` 收集器实现完整，但**产品链路上零调用** —— 全仓只有
`benchmarks/demo_spine_local.py` 与 `benchmarks/harness_pass_rate.py` 调它。
`ArtifactStore.save()` 只写 `code.*`/`sketch.json`/`result.json`/`verification.json`/
`benchmark.json`，全仓没有报告模块。跑完一次真实验，**没有任何文件**能回答「这一轮哪些事
没能确立」。同族的小一号：入库判据的拒因在 `conductor._save_to_db` 里只被 `print` 一次。

**修法**：`operator_agent/report.py` → 产物目录里的 `report.md`（best-known-good +
逐轮证据链 + 我无法确立的事 + 指纹/续跑入口），在 `Conductor` 循环结束、**入库判定之后**
写出（`result.json` 与快照都早于那一刻，所以拒因只能靠这件产物带走）。两条形状纪律：

1. **空章节必须带依据。** 空清单有两种来源（「都站得住」/「压根没收集」），在产物里长得
   一样；为空时把逐项核过的 8 条印成 `absence_basis`，核不过的项变成条目。最难的一条是
   心跳的三态：`False`=检查过是好的 / `True`=失败 / **缺键=本次与心跳无关**（不许算过）
   —— 这不是我加的纪律，是 `verifier.py:1290` 那三行注释的原话。
2. **`can_persist=False` 不是「测不准」，是「不许记住」**：它不进无法确立章节，而是在
   best-known-good 里单列一行「这条没有进长期记忆」。

**顺手补上的三条死读信号**（此前算了没人读）：峰值未实测、三态缺键（缺 `speedup` ≠ 没加速）、
资格位 `can_persist=False`。措辞与前置项**逐字相同** —— 去重键是 `(claim, reason)`，差一个
词就会被读成两件事（真跑 demo 时抓到同一件事被数了两遍，见 §五）。

**守卫两组**（`tests/test_report_deliverable.py`）：A 组纯函数逐条成对（8 项前置各坏一次
⇒ 必须有自己那条；全好 ⇒ 一条都不许有），B 组**真跑 `Conductor.execute`** 断言产物目录里
真有 `report.md`。变异：删掉 `conductor._execute_inner` 结尾那次 `write_report(...)` ⇒
B 组 2 红、A 组全绿。

## 四、③ §14-9 资格审计的对照（中心主张第一次可证伪）

**设计自己承认的空白**（§19.4 第 2 条）：「§4 那层『资格审计』在上述任何工作中都没有
对照。既可能说明它是真空白（差异化机会），也可能说明它在主流的**同卡、短程、单次评测**
协议下并不必要 —— 噪声被评测口径掩盖了。」

而设计开头第 30 行立的门是「真机 §14 冒烟之前，不对外说资格审计带来收益」。问题在于：
**§14 的八条只测它在不在岗，没有一条测它在不在值** —— 门后面根本没有那条路，于是这句话
永远无法翻页。

**补上的第 9 条**（设计 §14）：

- 两臂只差一件事：B 组让资格位不再拦任何东西（判据照算照记，只是后果不受限）。
  ⚠️ 这个「关掉」**不许做成产品开关** —— §10.5-5 说 agent 不能编辑自己的尺子，一个
  「一键关掉安全门」的环境变量就是那把尺子，它会先被用在无人值守的夜里。B 组只能在
  harness 侧 patch 出来。
- 三个数全部从 `iteration_history` 离线可算：最终 `best`、真值测量轮数（§10.2 的货币）、
  **脏永久后果**轮数。
- 判决五态，其中两态是这个比较器的重点：
  - **`没打到点上`** —— B 组一次都没出现「本该被拦」的读数。从「门没被需要过」推不出
    「门没用」（与报告里「空清单必须带依据」、`assess()` 里「地板未知 ⇒ 记未做检查」同一条纪律）。
  - **`没有收益`** —— 审计有过用武之地而 B 的 `best` 不劣 ⇒ 白花机时 + 留下脏后果，
    **这一向必须写进报告**。设计缺的正是它。

**为它补的血缘**（这是本件真正的产品改动）：`iteration_history` 里加两格 ——
`eligibility`（五位）与 `permanent_effects`（`best_updated` / `recipes_disabled` /
`stagnation_counted`）。理由是仓里已有的那句原话：`measurement_validity` 进血缘是为了让
「有多少轮的读数有资格驱动闭环」**可以离线统计**；而**后果**从来没被记过，于是
「一个不可信的读数有没有真的永久改掉配置 / 覆盖 best」出了循环只剩一个最终的
`disabled_recipes` 集合，归因不到轮。加完立刻被自己的守卫抓到（`test_harness_pass_rate`
的「假血缘不许比真血缘少键」），夹具同步补齐。

**比较器**：`benchmarks/ablation_eligibility.py`（`--arm-a/--arm-b` 给两个产物目录，
`--selftest` 跑五态夹具）。带宽取**仓内**口径 `NOISE_BAND[uninformative]` = 2%（跨运行比较
的可信度低于轮内比较，而轮内真机离散只有 0.13% —— doc 63），不自己发明数字。

**状态**：比较器与五态判据落地（18 条用例，含「不许有开关」的政策守卫）；
**两臂真机对照 ⏳ 未跑**（同卡两次完整循环，要 LLM）⇒ 「资格审计有收益」今天仍然不许说。

## 五、这一趟**没有**覆盖的（明写，别让台账读成全覆盖）

1. **`probe_peak` 本体没实现。** 只做了「没实测 ⇒ 出口关闭」这一半；探测本身（已知好
   GEMM 打到真实峰值 + 按精度发布实测值 + 失败即关出口）仍未做。今天所有真机的分母仍是
   规格/推导表 —— 只是**不再**被当成收敛证据。
2. **§14-9 的两臂没跑。** 比较器是判据，不是证据。五态里的「有收益 / 没有收益」在本仓
   今天**没有任何实测样本**，带宽 2% 也还是借来的（`NOISE_BAND[uninformative]`）。
3. **「事后被推翻的长期记忆条数」仍算不出来** —— 它需要后续一次运行来推翻，单次对照算不出。
   比较器不假装能算（边界写在模块 docstring 里，而不是留一个恒 0 的假指标）。
4. **报告只是一次运行的横截面。** 它不跨运行比较，也不替代「不可变实验日志」那件交付物；
   逐轮 metrics 仍然只有最后一轮完整（证据链表里已明写这条口径差别）。
5. **两处对照的因果强度有限。** 五态里的 `没有收益` 是**单协议下的方向性观察**（一批轮次、
   一台机、一个算子族），不是「资格审计无用」的证明 —— 与 doc 63 §五、设计 §19.4 同一口径。
