# 34 · util 快照去污染复核：结论是它今天没在响，而那句「约 1 秒窗口」是错的

> 日期: 2026-09-26 · 机器: `algorithm-h20` GPU 2 · torch 2.14.0+cu130 / triton 3.8.0
> 关联: [doc 31 三态验证](31-测量有效性三态真机验证.md) · [doc 33 离散度门](33-离散度门真机验证.md) · [doc 36 交错 A/B](36-交错AB真机验证.md)
> 复现: `python3 benchmarks/verify_util_decontamination.py --probe` 与 `--reps 8`

这是 README「待补」表里那条的正式复核，顺带把 D3 新产出的 `paired_speedup_dispersion` 的真机分布一次采齐 —— D4（四态判决）的阈值要按它定。

---

## 一、要判的两件事

1. `cf2d50b` 之后的 util 采样是「隔 1.2 s 采两次取 min」，动机是 doc 33 第三节实测到的**自污染**：真空闲的卡上，紧挨着自己一轮 benchmark 之后去采会读到 10-34%，足以把一次干净的测量误判成「基准被污染 → 加速比不可比」，进而让 Conductor 静默停止计停滞。当时把「触发率从几乎每次降下来」当成理所当然的收益，**没有复核过**。
2. D3 每次 L3 多回报了一个 `paired_speedup_dispersion`（逐块比值的 iqr/median）。它读起来像「这次加速比该信几分」，但没人验证过它和**真实的跨次散布**是什么关系。D4 要把这类量变成判决带宽，必须先知道它是偏大还是偏小。

---

## 二、第一个零结果是空转的（第三次踩同一课）

同一 shape 连跑 8 次 L3，三个 shape 共 24 次：

| 形状（档） | 现规则(min) 判污染 | 旧单次快照 would-be | first > second 的轮数 |
|---|---|---|---|
| layernorm 1024×768（uninformative） | 0/8 | 0/8 | 0/8 |
| layernorm 16384×6144（degraded） | 0/8 | 0/8 | 0/8 |
| matmul 4096³（valid） | 0/8 | 0/8 | 0/8 |

`gpu_util_samples` 24 次全是 `[0, 0]`。

这个 0% **不能**用来判修复有效。原因：每一次 L3 都是**新的远端进程**（ssh → uv → `import torch`），到自己的核排空之后再过好几秒才采样 —— 那个「测量前」的采样点离上一轮 benchmark 的尾巴隔了好几秒，本来就撞不上。也就是说这套跑法对「自污染」没有检出能力，跟 doc 36 第二节（忙等注入不留状态）、doc 35 第五节（两臂共享同一份信息）是同一类错误：**先确认量具能看见你要看的东西**。

---

## 三、把量具挪到能看见的地方：进程内探针

`--probe` 在远端**同一个进程**里跑满 8192² fp16 matmul，然后按 0 / 0.3 / 0.6 / 1.2 / 2.4 / 4 s 的延迟连采 6 次：

```
idle_before_burst: 0%
burst0.3s: t+0s=100%  t+0.3s=0%  t+0.6s=0%  t+1.2s=0%  t+2.4s=0%  t+4s=0%
   -> 现规则取 min(t+0, t+1.2) = 0%   旧单次快照 = 100%   阈值 5%
burst2.0s: t+0s=100%  t+0.3s=0%  t+0.6s=0%  t+1.2s=0%  t+2.4s=0%  t+4s=0%
   -> 现规则取 min(t+0, t+1.2) = 0%   旧单次快照 = 100%   阈值 5%
```

两条结论，一条支持修复、一条推翻它的前提：

- ✅ **机制是真的**：核刚停那一瞬读到 100%，远超 5% 阈值 → 单次快照必然误判。取 min 之后判 0% → 修复方向正确。
- ⚠️ **`_sample_gpu_idle` 的注释里「utilization.gpu 是过去约 1 秒窗口」这个假设与实测不符**：跑满 2 秒之后 **0.3 秒就已经回落到 0%**，不是 1 秒。所以 1.2 s 的间隔有 4 倍以上是纯代价（每次 L3 白等 ~0.8 s，占 L3 墙钟 6~13 s 的 6~13%）。已下调注释说明实测值，**间隔本轮没改**（L3 墙钟数字被 doc 36 引用过，改它该单独一轮）。
- 因此那句「触发率从几乎每次降下来」也**不成立**：在当前生产节奏（每个 action 一个新进程）下，旧规则本来也不会误报。这层保护的是**还没发生的那种未来** —— 常驻 runner / HTTP 模式下 L1/L2/L3 在同一进程里连着跑，那时采样点就会落进 <0.3 s 的窗口里。定性从「现在在响的警报器」改成「保险」。

顺带把两次原始读数（`gpu_util_samples`）沿 payload → metrics 搬了出来。只留 min 的话，上面这三条**一条都量不出来**，而「min 排掉的是自己的残留还是邻居的真占用」在生产里也永远无从查起。守卫 `test_raw_util_samples_survive_to_metrics` 断言它活着到 metrics，并把「判污染只能用 min、first 不许越权」钉住（把 `gpu_util_samples` 从 verifier 的搬运元组里删掉即变红，已实测）。

## 四、`paired_speedup_dispersion` 的真机分布 —— D4 的阈值不能照抄外部值

同一批 24 次 L3（无注入，卡上其他进程 7 个，util 全程 0%）：

| 档 | 形状 | 加速比 median | 跨 8 次的真实散布 (iqr / 范围) | `paired_speedup_dispersion` median (范围) | 后者 / 前者 |
|---|---|---|---|---|---|
| uninformative | LN 1024×768 | 1.3495 | 0.66% / 1.3261~1.3540 | **0.0248** (0.0190~0.0400) | **2.8×** |
| degraded | LN 16384×6144 | 1.3980 | 0.13% / 1.3960~1.3995 | **0.0114** (0.0109~0.0129) | **6.3×** |
| valid | matmul 4096³ | 1.0564 | 0.02% / 1.0563~1.0569 | **0.0016** (0.0010~0.0025) | **8.0×** |

三条要用起来的读数：

1. **它单调跟随档位**（0.0016 → 0.0114 → 0.0248），所以确实是个「这次测量有多可疑」的信号，单次运行就能拿到，不用重复跑 —— 这是它相对跨次散布的实际优势。
2. **但它系统性偏大 3~8 倍，而且越干净的档偏得越多**（valid 8×，uninformative 2.8×）。原因很直白：它量的是**单个样本**的逐块比值散布，而决策用的加速比是 median（几千个样本的 median 比单样本紧得多）。所以**不能**把它直接当 D4 的判决带宽 —— 拿 0.0016 当「SAME 带」会把 valid 档里 8 倍于真实噪声的差异判成「无差异」。
3. D4 该用的带宽是第三列（真实跨次散布）：本机安静时 valid 档 **0.02%**、degraded 档 **0.13%**、uninformative 档 **0.66%（范围宽到 2.1%）**。对照外部落在锁频独占机上的 FAST/SAME 阈值 0.5%/2%：
   - valid 档：0.5% 是真实噪声底的 **25 倍** —— 太粗，会把真实的小改善判成「没变」；
   - uninformative 档：0.5% **小于**实测范围 2.1% —— 所有结果都会落进 SAME/AMBG。

   这正好证实 doc 20 里 D4 当时那条拒绝理由（「0.5%/2% 是锁频专用机的值，直接套用会让共享机器上全部落 AMBG」），而且现在有了本机的数。**建议 D4 的带宽按档位分别定**，而三态里的 `can_gate` 已经天然挡住了 uninformative 档不做 FAST/SAME/SLOW 判决 —— 也就是说 D4 不需要发明新的门，只需要给 valid 档一个 ≈3× 真实散布的带（本机约 0.06%~0.1%），并把这个带随 `launch_dominance` 分档存下来。

## 五、这一轮改了什么

| 位置 | 改动 | 为什么 |
|---|---|---|
| `run_kernel.py` `_sample_gpu_idle()` | 多回报两次原始读数；docstring 把「约 1 秒窗口」换成实测的 <0.3 s，并写明生产节奏下这层是保险不是警报器 | 只留 min 就不可审计；注释里那条假设已被推翻 |
| `run_kernel.py` 动作处理 / `verifier.py` 搬运元组 | `gpu_util_samples` 一路带到 metrics | 「算了没人读」是本项目反复出现的同一类缺陷 |
| `tests/test_measurement_validity.py` | 新增 `test_raw_util_samples_survive_to_metrics`，并断言判污染只看 min | 防将来有人「顺手」改成拿 first 判 |
| `benchmarks/verify_util_decontamination.py` | 新增：三档连跑 N 次的污染触发率 + 反事实（旧规则会响几次）+ 配对散布分布，以及 `--probe` 进程内机制探针 | 第二节的空跑与第三节的探针必须是两个东西，否则又会拿空转当结论 |

全量单测 325 passed / 4 failed（4 个长期红）。
