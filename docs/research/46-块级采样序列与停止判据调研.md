## 一、为什么单独做这一篇

账本里 D5（噪声导向停止）是唯一挂着「地基已就位」却没动的测量项，而它的地基其实是个
**没人读的字段**：`paired_speedup_dispersion` 自 D3 落地起就只是「算了没人读」清单上的一行
（doc 20 §六第 1 条）。要给它找读者，先得回答两个此前只凭直觉的问题：

1. 拿 `iqr/median` 当「还要不要继续采样」的信号，它到底看不看得见我们要防的那种东西？
   doc 33 只证了它对**单点离群**不敏感；这台机器上的真实失效是**邻居插队占掉一整块连续时间**。
2. 「判决稳定就停」这件事有没有先例、有没有人量过它的风险？

## 二、别的测量框架实际怎么停

| 框架 | 实际停止规则（读代码，不是读文档） | 出厂默认 | 分级 |
|---|---|---|---|
| `triton.testing.do_bench` | 5 轮估时 → `n_repeat = max(1, int(rep_ms/est))`，**没有最少样本数**；返回 **mean** | `warmup=25`, `rep=100` ms | ✅ `testing.py:302-337`（vendored） |
| `do_bench_cudagraph` | 样本数钉死在 `n_retries=10`（硬编码），抬 `rep` 只让每个样本更粗；**不冲 L2** | `rep=20` ms | ✅ `:146-186` |
| PyTorch `blocked_autorange` | 块长调到计时开销 <0.1%，跑到累计 ≥`min_run_time` | `min_run_time=0.2` s | ✅ `utils/timer.py:305-382` |
| PyTorch **`adaptive_autorange`** | 全场唯一一个「按离散度停」的：`len>3` 后 `iqr/median < threshold` 就停 | **`threshold=0.1`** | ✅ `:384-445` |
| Inductor `Benchmarker.benchmark_gpu` | `min(100, 25ms/est)`，下限 1；返回 **min** | — | ✅ `benchmarking.py:643-760` |
| `nvbench` | 默认 `stdrel`：≥`min-time` **且** 相对 SD <`max-noise`，或噪声序列自身稳住（尾窗 ≥64，`Var(noise) < (0.05·mean)²`） | `max-noise=0.005`, `min-time=0.5s`, `min_samples=10` | ✅ `detail/stdrel_criterion.cxx` 等 |
| `asv` | **不是**噪声驱动：把 `number` 标定到 ~10 ms/样本后固定循环 | `max_repeat=10`, `max_time=20s` | ✅ `asv_runner/benchmarks/time.py:112-210` |
| KernelBench | 固定 trials，返回 **mean** | `num_warmup=3`, `num_perf_trials=10` | ✅ `timing.py:201-246,602-620` + `eval.py:636` |
| FlashInfer-Bench / MultiKernelBench | 固定：3×50 CUPTI / 100 trials | — | ✅ 各自 `timing.py` / `performance.py` |

三个要点：

* **没有一家按「A/B 判决是否稳定」来停。** `adaptive_autorange` 和 `nvbench` 的 stdrel 都只看
  **单臂**自己的散布。所以 D5 想要的东西在文献里没有现成先例 —— 这是负证据，不是缺陷。
* **`adaptive_autorange` 的阈值是 0.1（10% IQR）**，比我们按档位存的 0.1%~2% 宽带一个数量级。
  它的判据形状和我们的 `iqr/median` 一模一样，也就是说：**如果我们打算照抄一个真实存在的规则，
  抄来的就是「对成段污染同样迟钝」的那一个。**
* **KernelBench 出厂口径是 mean 而不是 median**（`get_timing_stats` 返回 mean/std/min/max，
  `eval.py:636` 取 `stats["mean"]`）。我方 L3 全程 median，所以任何「我们的数与 KernelBench
  可比」的表述都要限定口径 —— doc 42 引它的 60~85% 达成率时没碰这条，但记下免得以后踩。

## 三、序贯统计能不能拿来用

答案对**这台机器的噪声形状**是偏否定的，而且否定的理由很具体：

* **分位数的 time-uniform 置信序列**（arXiv 1906.09712）是理论上唯一对得上「反复看一个 median
  的置信区间」的工具，✅ 摘要明写它建立在 **i.i.d. 观测流**之上。邻居插队让同一块内的样本相关，
  i.i.d. 直接破。
* **SPRT / mSPRT / always-valid p 值**要求似然比在 H0 下构成非负鞅；一个 10³ 倍的单侧尖峰
  不在任何被假设的分布族里，破掉的是**鞅性质本身**，不只是功效。
* **能用的**是把分析单位从「样本」抬到「块」：两臂按块交错时，块与块近似可交换，而块内不。
  `asv` 的手搓 `mann_whitney_u`（✅ `asv/_stats.py:75-148`）因此是可直接搬的形状 —— 纯 Python
  零 scipy、`max(m,n)≤20` 用精确零分布、**保守的 tie 处理**（CUDA event 计时高度量化，这条最要
  紧）。弱点是 >20 会静默退到正态近似 + tie。
* 真正**不需要任何分布假设**的判据是「一致才停」：前 k 块的 median 全部落在判决的同一侧。
  它对单个离群免疫，正好是这台机器上噪声的形状。

## 四、真机：先确认量具看得见一段**已知**的污染

`benchmarks/probe_block_series.py` 直接调**已部署 runner 里的** `_bench_pair_interleaved`
（不是仿写），候选是一个 Triton 缩放核、基线是 `torch.mul`。污染不是「希望邻居来」，而是
**我们精确知道落在哪几块**的人造抢占：候选臂 host 侧在运行到 55%~75% 时每次多睡 1.5 ms。
哪些块被击中不靠预测 —— 用候选包装器的总调用数反解测量窗口
（`total = 5 次估时 + n_warm + n`），反解失败会直接报 ❌ 而不是伪装成「没有影响」。

```
[干净] n=2021 块长=10 块数=203 候选 median=0.00832 ms 基线 median=0.00829 ms
  全局 iqr/median = 0.0309

[抢占] 注入了 404 次候选调用 (=1.5 ms host sleep), 应落在第 111~151 块
  干净块 median=0.9981 被污染块最差=0.0054 → 块级放大 ×185.87
  全局: 候选 median 0.00832 → 0.00832 ms (×1.00)
  iqr/median: 0.0309 → 0.0388
```

一次 20% 时长、**幅度 186 倍**的抢占，在两个聚合口径里的表现是：全局 median **0.00% 变化**，
`iqr/median` 从 0.0309 走到 0.0388（+26%，相对任何合理阈值仍然「一切正常」）。
这是 doc 33 那条「iqr 对单点离群不敏感」的**第二半**：它对成段污染同样迟钝，因为干净样本
按数量赢。而块序列不但看见了，还把它定位到了第 111~151 块 —— 正是注入的那一段。

⚠️ 本轮又一次栽在「判据方向写反」上：第一版把放大算成 `max(dirty)/median(clean)`，而比值是
`基线/候选`，候选变慢让这个数**变小** —— 于是量具明明看见了 ×186，脚本却打印「❌ 看不见」。
一个会自我批评的错误判据比一个缺失的判据更难发现，因为输出看起来像是在诚实。

**顺带的独立发现**：同一个核、同一台卡、同一份参数，三次运行的样本数分别是
2171 / 2021 / 3084。`REPEAT_MS_BUDGET/est` 里的 `est` 只跑 5 轮不冲 L2，于是
**采样数本身就是不稳的**。任何「跑满 N 个样本再判」的表述在这里都不成立，而 D5 想替换的
恰恰是这个固定次数。

## 五、截断判决：false-stop 的初步曲线

把同一个 run 的前 k 块拿来重算 D4 判决（`min_required=1.0`，valid 档带宽 0.4%），与全量判决比：

| run | 全量判决 | 前 k 块与全量不一致的 k | 最早出现在 |
|---|---|---|---|
| 干净（203 块） | SAME | **10/203** | k=1 |
| 污染 ×186（309 块） | SAME | **110/309** | k=1 |

读法：即使完全没有污染，「随便在哪一步停下来」也有 ~5% 的截断点会给出不一致的判决，
而 `k=1` 就翻说明**只看第一块几乎必然错** —— 这正面否掉了「块间一致就停」里
「一致」二字被理解成「从第一块起一致」。受控污染下这个比例涨到 36%。

## 六、本轮吸纳了什么、没吸纳什么

**吸纳（已落地，只观测）**：runner 现在按块输出 `block_ratio_medians`，verifier 搬进
`metrics`。理由是第四节那组数 —— 块序列是目前唯一被证明**看得见**这台机器上真实失效形态的量，
而它此前被摊成一个数扔掉了。非 CUDA / 旧 runner 时保持 `None`，不折成空列表
（空列表会被将来的停止规则读成「零块 = 无证据」而不是「没证据」）。

**明确不吸纳（本轮）**：

* **任何停止规则。** 第五节那两条曲线是在**人造污染 + n=1 个 run** 上量的，不是这台机器的
  真实邻居分布；把它当阈值就是造一条没有分布支撑的死判据（D2 同一课）。
* **分位数置信序列 / SPRT**：前提假设（i.i.d.、指定分布族）与第四节观察到的噪声形状不符。
* **`nvbench` 的 stdrel**：它判的是单臂的相对 SD，恰好是「看不见两臂之间错位」的那类信号。
* **逐样本 shield**：块是 shield 进出与交错日程的最小单位，这是 `run_kernel.py` 里既有
  的、由反作弊语义决定的约束，不因测量需求而改。

## 七、改判条件

1. 生产语料里攒够 `block_ratio_medians`（现在随每次 L3 进 metrics）之后，把第五节的截断实验
   在**真实邻居污染**下重跑：需要 ≥几十次运行，其中至少若干次是真被抢占的。
   那才有资格谈「停止要留几块」和 false-stop 的容忍值。
2. 「最少 B 块 + 判决一致」里的 B，先验应当来自第四节：污染占 20% 时长时，一致性从第几块开始
   再也藏不住 —— 这条要等真实分布。
3. 如果 `est` 造成的样本数漂移（2171/2021/3084）在生产里也这么大，那么**先修估时口径**
   （例如要求最少 20 轮估时，或把 `n` 固定成 2 的幂）再谈停止规则，否则比较的不是同一件事。
4. 若接入的机器不再是共享卡（邻居消失），第四节的判别实验要重做 —— 它证明的是这台机器的形状。
