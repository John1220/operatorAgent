首次完整 L2 时间从每项 CLI 监督者 `run-status.started_at` 到对应 L2 完成事件的墙钟差近似计算，不含外部设备预检与声明准备。事件与候选源码及契约哈希绑定，调用数和 usage 取事件当时的模型账本水位。最终完整 L2 必须有与最终选择源码和契约匹配的通过事件，不能根据进程退出码推断。

LayerNorm 初始候选的完整 L2 失败，Fixer 使用一次模型调用产生修改后的候选，最终完整 L2 通过。三项生成均使用当前普通 Coder 路径；没有启用 CoderPipeline 或恢复 Q1。内建 L2 包含有限的边界、值模式和非连续布局覆盖；生产声明没有注入历史质量集的额外 primary/holdout，不能把本轮称作完整质量集验收。

四项所选候选的 L3 均为 `uninformative`、`measurement_can_gate=false`，启动地板分别占约 74.5%、71.8%、77.9%、78.2%。因此：**完整正确 4/4；性能确认达标 0/4；性能结果未知 4/4**。这里的 0/4 是已确认达标数量，不表示四项性能已证实不达标。由于无有效首次性能测量，未启动不合格的独立性能确认；日志中的原始加速比不能作为性能成绩。下一次性能评测应另行冻结更适合测量的形状和预算，不能事后替换本批样本。

上述所选候选的 L3 回执分别记录 1,824、2,334、2,855、1,967 个配对样本；每项基线的请求测量次数为 30。配对样本数与请求次数是不同口径，也不是 GPU launch 总数。即使样本很多，受启动地板主导的读数仍不能取得裁决资格。
