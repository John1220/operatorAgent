- [x] **M3 验证发送前硬门。** 在 `agent/request` 正规限制单次输出，在 `llm/stream` 调用下一层前再次核对实际控制参数并原子预留；超限不触达 provider。不能只写提示词，也不能修改被冻结的请求对象。

- [x] **M6 完整结算与对账。** 失败、取消、未完成和小于预留的实际输出均不退款；缺失 usage 保持 unknown。明确用量、输出预留与费用的区别，核对 provider 超出预留输出时后续请求会被阻止。
- [x] **M7 补真实宿主集成测试。** 新增真实 DSH + 本地 provider 的测试：准备调用后只放行限定次数，下一次在发送前拒绝；重启同 session 后仍无新增额度。测试框架的停止条件与产品硬门分别留证。
- [x] **M8 验证默认安装配置。** `hostModelBudget`、服务依赖、随包文件和 profile 完整 config 覆盖均正确；状态输出能显示实际模型额度与明确的未绑定/无效/旧 policy 状态。
- [x] **M9 验证额度耗尽后的可达出口。** 协调 Python 的 final 验证预留与 DSH 发起终评、汇总所需的模型次数/输出预留；不足时如实停止，不把未完成终评说成已交付。即使主模型已不能再请求，用户仍须无需模型即可查询停止原因和剩余额度、取得已有候选/报告并取消在飞任务；补对应负向验收，不靠增加额度或新建任务恢复这些基本操作。

**M 组出口条件：** provider 观察到的派发数不超过冻结额度；总输出预留不超限；失败/取消/重启不重置已花额度；无账本、坏账本、丢失绑定和不确定 owner 不会静默获得信用；预算停止后仍能查询、取回证据和取消。

## 5. P0：恢复与用户中途干预

- [x] **R1 暴露只读恢复入口。** `operator_resume` 复核原契约和账本，返回原任务身份、剩余额度、最新完成轮、最后正确候选与下一步工具参数；不新 prepare、不改截止、不自动清理未知记录。
- [x] **R2 完成 DSH 进程恢复。** 从同 session 的持久 prepare/resume 回执恢复绑定，并在首个后续模型请求前生效；忽略 fork 继承的其他会话绑定。未完成的模型调用保留不确定状态，只有确认旧 owner 已退出后才能标 abandoned，仍不退款。
- [x] **R3 验证旧任务与坏状态。** 旧 policy 缺少模型字段时不能自动补额度；契约漂移、损坏账本、未知在飞模型/验证、过期任务及已终评任务必须有明确结果，不重新打开开发。
- [x] **R4 验证中途追加要求。** 用 DSH 原生用户消息/steer 或 followup，在下一轮主模型请求中核对新增要求，并检查实际候选采用该要求；保持同一契约时继续原预算。
- [x] **R5 验证冻结条件变更。** 用户改变 shape、精度等判据时，保留旧任务并明确建立新契约，由用户显式 `/op new` 授权下一项独立任务，可继续使用同一主会话；不得在旧 run 原位改判据，也不得将预算耗尽解释为自动新建任务的授权。
- [x] **R6 完成真实恢复闭环。** 真实 DSH 先取得材料/产生候选，再停止进程并恢复；自主继续验证、修复或独立终评。核对 task_id、原 deadline、调用历史、候选与契约哈希，保留全部失败尝试。

**R 组出口条件：** 恢复后既不丢失已验证候选，也不重新获得预算；新用户要求确实进入外层上下文；未知状态没有被改写成成功、零成本或已停止。

顺序：**固定 C1–C2 验收条件 → M1–M4 接线 → M5–M9 预算集成 → R1–R6 恢复/干预 → U1–U5 生命周期修正 → F1–F6 封版**。C 组贯穿后续回归，不另起一套编排器。先用本地 provider 验证拒绝与恢复，再开始有明确调用/时间上限的真实模型和 H20 任务。

每项完成时记录对应源码提交、工件哈希、命令和结果路径。所有派发与失败保留；新一轮任务使用新的计划身份并说明原因，不能通过增加额度、重置原账本或删除失败换取“通过”。模型预算不等于精确费用/GPU 时间上限；服务商执行是否停止仍以可观测回执为准。

多算子扩展、性能诊断/搜索增强、第二宿主、多代理并发与通用 Watchdog 不在本轮封版前置范围，继续按既定演进路线推进。

功能可用性与收益分开记录。可以沿用已有日志观察成功率、首次完整 L2 时间和模型用量；缺少配对条件时不宣称降低成本或提高质量。正式收益对照另按计划推进，不新增为本版封版门槛。
