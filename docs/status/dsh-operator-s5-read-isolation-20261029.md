## 实际修改

- `benchmarks/s5_seatbelt.py`：在整个 Node/DSH 进程外层使用 macOS `sandbox-exec`。文件读取和写入分别默认拒绝，再允许所需运行时、各组自己的 HOME/work/tmp 及有限只读配置。子进程继承外层限制；Apple Events 发送禁用。profile 丢失、被替换、runner 缺失、公共运行时漂移均直接拒绝，不会无沙箱重试。
- `benchmarks/s5_arm_env.py`：显式 `isolation_runtime` 启用隔离启动。B/C 从独立公共包副本加载相同 core；C 额外加载插件；A 只复制标准库公共验证客户端，不获得 core import 路径。普通入口默认配置保持原状。
- `benchmarks/s5_isolation_probe.py`：用本地脚本化假模型驱动真实 DSH，测试越界读取和两轮 mock 开发反馈。报告绑定沙箱实现、公共运行时内容及三组可见性；验证时还对照当前 core 的 73 文件协议身份和插件源码。
- `benchmarks/s5_formal_run.py` / `s5_workflow_preflight.py`：新预检必须提供通过的隔离报告，在读取凭据或派发真实请求前校验；每格启动前重新校验。受试工作区在仓库外，监督器的计划、账本、转录及评测证据保存在隔离边界外。工作文件归档不跟随符号链接，避免归档阶段将私有数据带入证据包。

公开 core 包本身含有的判定逻辑可被 B/C 阅读，这是 core 安装面的组成部分；未声称它保密。被隔离的是其他组文件、原始开发仓库与历史结果、宿主用户目录，以及监督器私有文件。

## 两项兼容性处理

1. **工作区必须放在仓库外。** DSH 会向上探测 Git 根；放在原仓内部会在读取 `.git` 时被外层沙箱正确拒绝而退出。受试 HOME/work/tmp 使用仓库外的私有临时目录，证据由监督器保存，原仓不因此获得读取许可。
2. **macOS 不允许嵌套初始化 Seatbelt。** DSH 内层原有写入围栏在外层沙箱内报 `sandbox_apply: Operation not permitted`。隔离启动中显式设置子进程的 `DSH_PERMISSION_MODE=danger-full-access`，含义是将内层职责委托给必需的外层文件白名单；外层仍强制执行读写限制。启用该设置会同时打上“外层必需”标记，缺少外层配置时拒绝启动，不存在自动降级裸跑。用户的真实 DSH profile 未改动。

早期 v1（仓库内 Git 探测失败）、v2（嵌套沙箱失败）以及中间 v3 材料均保留；最终结论只采用 v4 和最终回归。必需的系统读取包括根目录本身、系统库、Python 库（排除 ambient site-packages）及公开 shell 选择配置，不开放整个用户 HOME 或共享临时目录。
