# S5 流空闲超时诊断与修正（2026-10-30）

状态：**无模型复现与修正验收完成**，相关回归 183 项通过。已冻结并启动包含本修正及监督工具说明修正的新探索性 24 格批次，真实结果待执行完成。

## 已确立的原因与限制

旧批第二轮首格报 `pi-ai stream idle timeout after 300000ms`。本机实际安装的 `@deepseek-ai/dsh-llm-pi-ai` provider 配置支持 `streamIdleTimeoutMs`，默认 300000；适配器等待转换后的模型流事件时使用该 watchdog。S5 的监督 transport 单请求墙钟上限却为 900 秒。因此，适配器可以在请求仍处于监督预算内时先退出。

上述配置错位已通过同一已安装 DSH 适配器的本机假 Responses 服务复现；它不解释旧请求为何持续空闲，也不证明服务商、网络或适配器的底层停顿根因已消失。网关历史 failures 为空仍不能作为“上游没有问题”的证明。

## 修改范围

- `s5_arm_env.build` 增加有界的可选 provider `streamIdleTimeoutMs` 参数，并记录实际配置。未指定时不改变适配器默认值；不修改 DSH 安装文件或用户 profile。
- 新 study 计划显式冻结 `stream_idle_timeout_ms=930000`，A/C 都按同一参数启动；网关的单请求硬截止仍为 900 秒，模型/开发会话仍为 2400 秒。模型 medium、32K、调用/输出额度不变。
- study 加载拒绝重新改回其他 idle 阈值的计划漂移。已有冻结源码/结果不覆写，旧候选计划不能直接作为新版本执行凭据。
- 对已知宿主 idle timeout 增加结构化诊断：错误类型、实际阈值、`upstream_root_cause=unknown`，仍分类为设施故障，不归为候选错误或调用预算耗尽；不退款、不加重试。
- 没有加入虚假 heartbeat、成功终止标记或无限等待。监督截止、断流和取消仍由已有进程监督处理。
