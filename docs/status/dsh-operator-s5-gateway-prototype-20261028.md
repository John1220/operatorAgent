# S5 预算网关：假上游验证（2026-10-28）

状态：**本文记录假上游联测，不具备正式 S5 放行条件。** 后续已单独完成 [一次真实模型预检](dsh-operator-s5-real-gateway-preflight-20261028.md)，但只覆盖 Completions 兼容路径，不改变隔离和正式对照的限制。

## 已实现和验证

- `benchmarks/s5_gateway_policy.py` 使用已有 SQLite 账本作为该路径的唯一共享预留门；外层与内层入口共享上限，最多两次，派发前登记，失败不退款。每条记录仅保存请求哈希及有限元数据；参与者标签来自入口配置，不是可独立证明的进程身份。当前所有响应及 usage 保守记录为 unknown/missing，包括完整的假响应。
- `benchmarks/s5_gateway_http.py` 提供只绑定本机 IPv4 回环的实验 HTTP 入口；`benchmarks/s5_gateway_transport.py` 只允许固定 HTTPS 上游或测试用回环 HTTP，不跟随重定向、不使用环境代理或自动重试，固定的上游凭据仅在内存使用，不转发客户端认证头。
- SSE 内容按事件增量转发；`finish_reason` 和 `[DONE]` 从出现起暂存，直到上游 EOF 与格式检查通过再放行。错误、截断和超时不会补造终止标记。实际 DSH pi-ai 对截断流返回 error 的行为已用假上游测试；这是所测客户端的行为，不是所有客户端的保证。
- `benchmarks/s5_gateway_supervisor.py` 在独立子进程执行上游传输，凭据、端点和请求经 stdin 传入，不放在子进程 argv、环境或文件；watchdog 对慢响应头、下游停读等情况终止归属进程组。直接子进程已回收不证明逃逸后代或服务商已停止；启动与清理宽限也会带来时间误差。
- 本机联测让实际 Python `LLMClient` 与已安装 DSH pi-ai 经两个网关入口访问同一假上游和账本：两次成功通过，第三次被共享额度拒绝；假上游只接收网关的占位凭据。还覆盖实际 DSH 截断流、慢上游超时、取消、无重试/重定向、并发额度、篡改和敏感信息不进入账本等。
- 上述组件、共享账本及 HTTP 联测合计 **71 项通过**。测试只使用 `127.0.0.1` 假上游和测试凭据，没有真实模型或 GPU；未重新运行整个项目测试集。

## 明确限制

回环监听没有客户端认证；同机进程可以访问或绕过网关，`participant` 标记也不证明请求来自哪一层。独立进程监督覆盖上游 worker，不构成系统级网络隔离，也不能证明远端 provider 中止或逃逸后代已清理。HTTP 请求入口自身的慢速上传与服务关闭时在途线程尚无严格总墙钟/清理证明。现有请求字节、输出预留和次数限制不是输入 token 或金额硬上限。

真实请求前仍须冻结 endpoint、模型、计费和凭据，并接入任务专属受限通道与监督器，验证无法绕行、取消与资源清理。不要同时对同一请求启用旧 DSH 共享账本 hook 或 Python 内层共享桥，否则重复预留；各自本地生产预算可以保留。未经上述验证，不把本原型称作完整隔离或正式 S5 预算保障。
