三项工作的主要成本及现有复用点：

1. **Linux headless**：需要兼容 Node、完整 Linux 原生依赖和可复现安装，再验证真实 headless agent、工具和配置；当前完整 CLI 拉入大量非实验必需组件，宜先评估精简依赖闭包。
2. **真实模型网关**：已有本机假 HTTP 网关及 DSH/Python 联测；要接真实服务，还需受限凭据持有、可靠转发流式响应、共享预算、故障/取消处理，以及防止客户端直接绕过。单纯把现有假适配器换成真实 URL 不能证明这些条件。
3. **统一 GPU 入口**：现有 CLI、验证器、SSH runner、输入保真和会话清理能力可复用；但现有真实后端依赖 SSH，不能直接暴露给隔离组，需增加受监督的受限入口，并分别验证候选执行隔离、设备独占、预算和远端清理。它不是几条配置就能完成的改动。

这些投入是严格 S5 对照的实验基础设施，并非插件核心功能。继续应先选取一个明确限额的纵向小试验，验证最小 headless + 假网关 + mock 验证闭环，再评估接真实 provider 和 GPU；不能把该试验结果当正式三组比较。
