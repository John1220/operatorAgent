## 1. 实际修复

工具契约 **7 → 8**，插件 **0.1.7 → 0.1.8**。完整协议见[资源证据边界](../design/resource-precheck-evidence.md)。

旧资源门存在四种独立误判：任意 FP32 累加器/文字污染所有存储宽度；逻辑 tile/累加器被当成 shared；autotune 按轴取最大值拼出不存在的配置；stage 数直接当作共享缓冲副本。这些代理还进入了候选剪枝和结构升级硬限制归因。

S3 以同一套 `assess_shared_memory` 校验/比较为准：显式共享存储契约或原生资源回执必须由 harness 在当前上下文确立并绑定；各缓冲区独立 dtype/shape/copies，缺失、动态或绑定不明即 unknown。不把所有存储统一替换成任务 dtype，不修改硬件上限或既有 1.2 宽松系数。

源码解析仅保留逐组配置和字面量摘要。单份源码回执不能覆盖 autotune、多 helper、多 launch 或动态编译配置。模板资源身份独立于去重键，包含后端、模板、实例化器版本及全部带类型参数；非法/错绑定参数不能剪枝。原生回执仍须由 harness 核验架构、编译 flags、任务 dtype 等上下文，不新增跨上下文缓存或用户注入接口。

## 2. 生产接线

| 入口 | 现在的行为 |
|---|---|
| Verifier L1 | 发布 `metrics.resource_precheck` 的状态、来源、字节和配置；unknown 继续编译，真实编译异常仍失败 |
| CoderPipeline | 与 L1 共用资源门；无证据的逻辑 tile 不再提前拒绝，不因资源未知修改语法门结论 |
| 模板/搜索剪枝 | 无明确存储证据时保留候选；可信超限、相同 slack 和全摘回退仍有正反例 |
| Triton 参数空间 | 不再仅靠任务 dtype/tile 公式删除轴值 |
| Conductor 升级门 | 未确立的逻辑占用不生成 smem/occupancy 硬限制；脏硬件指标保持未知而非抛异常 |
| S1 / S2 | 完整留存和取消语义继续使用原有入口；资源未知不授予正确性、性能或入库资格 |

兼容公式仍可算出特定假设下的逻辑代理值，但不进入拒绝、剪枝或硬限制证明。未知可能增加实际编译尝试，任务预算上限保持；没有借此新增真实实验。

协议源码身份由 **64 → 68 个文件**，补入 candidates、coder_pipeline、triton_matmul_template、agents 搜索入口；旧实验继续按漂移规则区分。S0/S1/S2 材料未覆盖或改写。

## 3. 历史证据与本地复现

S0 H04 明确 10-19 原目录不可恢复。不能宣称找回当次原核，也不能把 192 KiB 称为原生共享占用实测。

新增 fixture 从保留的 H07（FP16 输入、FP32 累加、原 tile 128×128×64）提炼源码模式，再改为文档中的 256×256×64；它明确标注**重建**，不执行该 Triton 候选。`reproduce_s3.py` 只从 S2 归档读取并校验旧 checker，在内存加载可信旧 harness，以同一输入比较新旧逻辑。

| 本地复现 | 结果 |
|---|---|
| 重建 FP16/FP32 源码 + 228 KiB 上限 | 旧 checker 拒绝，代理值 393216B；新版 unknown，物理字节为空 |
| 显式混合缓冲区合成契约 | A/B 各自 FP16、copies=2，work FP32，合计 196608B；不越既有拒绝阈值 |
| 显式 FP32 工作缓冲区 ×2 | 524288B，正确拒绝；不被 FP16 任务声明覆盖 |
| autotune `(256,16,16)` / `(16,256,16)` | 旧 checker 拼成不存在配置并拒绝；新版保存两组、物理占用 unknown |
| 模板两点 | 无证据都保留；仅给大点绑定可信合成回执后，大点被摘，小点保留 |

所有 layout/native 回执均是**受控测试合成数据**，不是本轮 GPU 编译或测量。当前没有把 runner 第一份 cache kernel metadata 自动升级为全候选证据。历史评估文档已追加更正说明，原始实验记录保留。
