## 1. 两臂做了什么

起点核两臂相同：`64×64×32`、`num_stages=2`，stride-aware。

| 臂 | 第 1 轮 | 各臂拿到的反馈 | 第 2 轮的改动 | 第 2 轮 |
|---|---|---|---|---|
| B（v0.7.2） | speedup 1.0364 / 1.0080 ms / valid | 只有 L2/L3 通过、speedup、median，**没有瓶颈轴** | 128×128×64 / stages=3（通用猜测） | 1.0047 / 1.0404 ms **变慢** |
| C（v0.8） | speedup 1.0346 / 1.0109 ms / valid | 诊断：`compute_bound`、达成率 **91.9%**、余量 8.1%（规格峰值口径）、轴 `tiling/pipelining` | 64×64×32 / stages=3（诊断的 pipelining 轴） | 1.0522 / 0.9933 ms **快 1.7%** |

两臂各自保留最好版本，各跑一次独立终评：

| 臂 | 终稿 | 终评 L2 | 终评 L3 | 终评 validity | 终评 speedup | median |
|---|---|---|---|---|---|---|
| B | `s0_kernel.py` | ✅ | ✅ | `valid` | 1.0354 | 1.01136 ms |
| C | `s1_kernel.py` | ✅ | ✅ | `valid` | 1.0516 | 0.99619 ms |

## 2. 结论：增量**未**确立

配对差值 **+1.56%**，小于预登记的 2.5%。按预登记规则：

> 这一对不构成收益证据，只作观测记录。不启动任何"v0.8 更强"的表述。

而且即便差值更大，这一对也**不能归因于插件**——见 §4。

## 3. 管道本身是通的

这一对真正验证掉的东西：

- 门在真机上跑通，`START` 才放行；
- 两臂都能在 4096³ 上拿到 **valid** 的终评（不是 degraded、不是 uninformative）；
- C 臂的 `optimize` 上下文在真实回执上给出了可用的诊断（绑定轴、达成率、余量、轴清单），且 `precision_and_accumulation` 轴因为核已在 tensor core 上被正确过滤掉；
- 终评能与提交源码绑定，两臂可比。

## 4. 为什么这次差值不可归因（必须记住）

| 污染项 | 说明 |
|---|---|
| 同一模型、同一连续上下文 | arm B 的改动是在我已看过 arm C 诊断之后写的 → **串味** |
| 非原生路径 | 插件未参与模型预算硬门；调用次数由记录自报 |
| 任务贴着峰值 | 该核已达规格峰值的 91.9%，登记余量 8.1%，改善空间本来就小 |

原生路径下，两臂各自在独立 profile 的会话里跑，模型只看得到自己那臂的上下文——那才是 R2 设计的样子。

## 5. 对下一对的结论

- **选有余量的任务**：4096³ 在 91.9% 峰值上，能证明的差异空间只有 8%，而预登记门槛是 2.5%——太窄。下一对应选一个已知离峰值远、且带宽可判的 shape/精度组合。
- **先解决串味**：原生 profile 路径（`desktop` = 臂 B，`v08-arm-c` = 臂 C）不是可选项，是这一对证明出来的必要条件。
- 系列计数：第 1 对**不可判**（不是"两臂都 valid 所以没差别"，而是"按预登记门槛没测出"）。若第 2 对也如此，按停止规则系列记 `unknown`。
