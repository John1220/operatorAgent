# 候选任务实测：余量在哪（2026-11-07）

同一天同一窗口（H20）对 5 个候选各跑一次朴素实现的 L3，目的是回答一个问题：
**哪个任务同时满足"门能过"（带宽窄）和"有可挖空间"（离峰值远、离基线远）。**

记录口径：余量 = 100% − 绑定轴利用率（`max(gflops_util, bw_util)`），分母是规格峰值。
基线差距 = 朴素实现相对 torch 基线的 speedup。

| 候选 | 精度 | speedup vs 基线 | 绑定轴 | 达成率 | **余量** | validity | L2 |
|---|---|---|---|---|---|---|---|
| matmul 4096³ | fp16 | 1.0354 | compute | 91.9% | **8.1%** | valid | ✅ |
| matmul 8192³ | fp16 | 0.9932 | compute | 92.3% | **7.7%** | valid | ✅ |
| matmul 2048×16384×2048 | fp16 | 1.0311 | compute | 93.7% | **6.3%** | valid | ✅ |
| **matmul 4096³** | **fp32** | **0.3545** | compute | **33.8%** | **66.2%** | valid | ✅（用 `input_precision="ieee"`）|
| relu 16384×6144 | fp16 | 1.0147 | memory | 81.2% | 18.8% | degraded（地板 14.0%）| ✅ |

## 结论

- **fp16 matmul 全族都贴着峰值**（92%±2%），余量 6–8%，而预登记门槛是 2.5% —— 在噪声边缘。
  第一对选 fp16 4096³ 就是踩在这里，现在有数据了。
- **fp32 matmul 是唯一余量充足又带宽窄的组合**：余量 66.2%、相对基线只有 0.35×、探针带宽 0.10%。
- relu 这类 memory-bound 余量 18.8% 可以，但**带宽 1.35%**，按"门槛 ≥ 带宽×10"要登记 13.5% 的效应才成立，性价比低。

## 三个测量副作用（都已核实）

| 现象 | 原因 |
|---|---|
| fp32 matmul 首轮 L2 失败，误差 0.27 | triton `tl.dot` 对 fp32 默认走 TF32；参考实现是严格 fp32。加 `input_precision="ieee"` 后通过 |
| matmul 1024×65536×4096 被拒 | `backing storage 总量超过输入字节上限` |
| relu 32768×16384 被拒 | `logical tensor 超过输入字节上限`（上限 256 MiB/张量，seed 路径 512 MiB）|

## 对第二对的意义

第二对改用 **matmul 4096³ fp32**，计划 `operator-v08-increment-r2-fp32-v2`（hash `99b575c17f0101e2`），
预登记效应维持 2.5%（带宽 0.10% × 10 = 1.0%，2.5% 有 25 倍余量）。

首版 `operator-v08-increment-r2-fp32`（hash `8d460f9454ad2531`）**已撤回**：它的门控继承了
fp16 探针——命令缺 `--dtype fp32`（preflight 缺省探 fp16）、channel 与 0.203% 带宽都是 fp16
那次的读数，而上面这行 0.10% / 25× 才是 fp32 探针的实测。当时 `validate()` 放行了它，因为
门控没和任务绑定。撤回发生在任何一对开跑之前（`outcome` 仍为 null），所以不是事后改判据。
现在门控与可判性**按任务取值**，校验器新增三条：门控 dtype 必须等于任务 precision、带宽的
两份副本必须相等、已撤回编号指名拒绝。archived 的那份 JSON 原位保留不改，证据树里另存
`preregister-fp32-v2.json`。

证据：仓外 `output/v08-candidates-20261107/`（每候选一个 run 目录 + `gate-fp32.json`）。
