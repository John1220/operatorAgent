# S5 最小完成计划（2026-10-29）

状态：计划已整理，尚未冻结或启动新的真实模型/GPU 批次。目标是完成当前限定范围的贡献对照，允许结果为有益、无明确增益或成本更高；不以“插件必须优于原生 DSH”为封版条件。

## 1. 本次完成什么

在固定任务、相同模型、正常测试条件和共同预算下，比较 A（原生 DSH + 公共测试材料）与 C（同一 DSH + 发布插件），观察预算内最终完整 L2 正确率及开发成本。

范围沿用[当前两组设计](s5-plugin-only-comparison-20261029.md)：外层模型写核、提交开发验证、读取反馈并自行修改，随后独立终评。C 通过正式插件说明和 MCP 使用功能，不能直接执行产品 CLI、导入 core 或阅读实现源码；两组均有同等 GPU 测试机会。两组任务提示相同，不额外强制 C 调用插件。C 未使用插件属于接入效果，保留在结果中。

内层生成、自动 repair/run/bench、GPU 性能调优和人工操作便利性评测不纳入本轮；不恢复暂停的 Q1。结论只覆盖该模型、这些任务、生产 L2 套件和上述功能范围，不表述为整个插件全面优于 DSH。新增这些能力须另立研究范围，不在本计划中顺带扩展。

## 3. 唯一新增样本：6 任务 × A/C × 2 次 = 24 格

采用已前瞻声明的 `benchmarks/s5_minimal_tasks.py` 清单，冻结前重算并核验哈希 `79fb8b03ee0514d67a354e24b78622fb668a7d27e3592ad3d1144ee2dc74bbd2`。不根据旧实验胜负改选任务，不宣称模型训练未见。

| 任务 | 主输入规格 | 精度 |
|---|---|---|
| Matmul aligned | `(M,N,K)=(96,128,64)`；A 为 `[M,K]`，B 为 `[K,N]` | fp16 |
| Matmul tail | `(M,N,K)=(37,53,23)`；A 为 `[M,K]`，B 为 `[K,N]` | fp32 |

每格从相同空白候选状态开始，由 DSH 编写；此前注入缺陷的修复演示不混入本分母。每次重复使用独立 HOME、工作区、账本和任务身份，不携带上一格源码/会话记忆。按任务及重复轮换 A/C 顺序，固定完整 24 格 schedule 后执行。

两组使用同一冻结生产内建 correctness suite、参考与容差。独立终评在 DSH 结束后执行且不回传模型；“独立”指调用与反馈隔离，不代表另一份隐藏测试。现有清单不等同于历史质量集的主输入/holdout 重放，也不证明对未知输入泛化。

## 4. 按顺序完成的四步

### P1：补齐最小驱动和共同判定

- [ ] 在现有 A/C 驱动上支持上述任务清单和 `repeat_id=1,2`，保持旧计划/结果可分析；新协议独立 schema，禁止复用旧执行哈希。当前插件限定驱动只固定三个任务、一次重复，不能直接运行 24 格。
- [ ] 将候选、调用账本、反馈、最终验证路径按任务/重复/组隔离；拒绝重派同一格及覆盖产物。
- [ ] A/C 使用相同最终源码提取规则：原始答复留存，接受纯源码或唯一明确 Python 代码块，多个候选/无法确定则拒绝；说明文字、无末尾换行和“未做开发验证但有终稿”等情况均有测试。不能给 C 专用修复模式的提取特权，也不能事后选取曾经通过的源码代替最终答复。
- [ ] 同一评估器与冻结契约核对最终源码 SHA256；同一格所有开发入口共用最多两次额度，最终预留只能由监督器使用。
- [ ] 24 格假模型/模拟后端跑完整排程和汇总，验证成功、数值失败、预算耗尽、设施 unknown、未执行和重复派发拒绝；不发真实模型请求，不跑 GPU。

交付：可重建的任务/排程、共同提取器、定向回归及一次完整无模型汇总。复用已有功能，不开发新的 agent 框架。

### P2：核清正式执行门槛，再冻结一个新批次

- [ ] 核验已有文件读取边界：A/C 都不能直接执行 CLI、导入 core、读取其他组、宿主凭据或私有账本；C 正常发现插件，公共测试入口两组均可用。
- [ ] 补齐当前仍未证明的模型网络唯一出口和预算旁路约束：实际 DSH 的 shell/子进程不能直连 provider、其他验证服务或宿主代理；辅助模型调用禁用或计入同一账本。以无模型探针验证正常路径可用、旁路被拒，不能只依赖提示或隐藏凭据。
- [ ] 核验 GPU 候选执行环境的文件/网络边界与归属清理，候选不能反过来读取监督器凭据、改写账本或获得额外验证。复用[已有隔离要求](s5-isolation-and-supervision-20261028.md)，不把外层读取探针当成远端执行隔离证据。
- [ ] 复核历史远端传输 unknown 的失败留存和停止行为；不能以近期通过推断旧故障已根治。缺结果继续 unknown，发生后停止派发。
- [ ] 冻结任务、两组工具面/正常产品说明、源码与依赖、模型/端点、预算、suite、顺序、停止规则和 GPU 身份；按当前设备资源生成新观察，不复制旧快照当凭据。

先以现有环境做具体差距审计和最小实现验证。若必须迁移宿主或大规模重建隔离，先形成成本与替代方案供用户决定，不自行扩大建设；门槛未通过时不启动正式 24 格，也不把探索性结果改标正式。完整对抗隔离未建立的事实必须留在报告里。

本计划只整理后续工作，不构成新批次已经冻结或新增模型支出已经启动的声明。

- [ ] 24 格按冻结顺序执行；普通候选拒绝、未使用插件和调用额度耗尽保留为模型/工作流结果，继续下一格。
