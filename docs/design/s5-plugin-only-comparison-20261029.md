## 研究问题

在相同任务、模型、基础开发环境、资源、预算和独立终评下，用户通过发布接口接入算子插件，能否提高预算内完成率，或减少开发过程中的调用和耗时？

比较的是插件及其后台能力通过正常产品接口带来的使用效果。core 仍是插件内部实现，不作为模型可直接执行、导入或浏览的额外开发工具。候选算子源码是两组都可以读写的任务产物，需与产品内部源码区分。

## 两组边界

保留 A/C 标识以便说明历史，但新协议与历史三组是不同实验版本。

| 项目 | A：原生 DSH | C：DSH + 插件 |
|---|---|---|
| 模型、原生 read/write/bash 工具 | 相同 | 相同 |
| 任务声明、初始文件、公开基础测试材料 | 相同 | 相同 |
| 模型直接执行 `operator-agent` / `python -m operator_agent` | 不提供 | 不提供 |
| 模型导入 core 包、浏览 core/runner 实现源码 | 不允许 | 不允许 |
| 插件及其正式 MCP 工具、工具描述、使用说明 | 无 | 有 |
| core 后台实现 | 不向参与者暴露 | 在插件后台运行，只经发布接口调用 |
| 开发反馈标准、验证次数、独立终评 | 相同 | 相同 |

“去掉 CLI 因素”指不把产品 CLI 作为模型可用工具，并不禁止 DSH 原生 shell 或通用 Python 命令。插件内部依赖 core，或为实现某个功能内部启动 CLI，属于产品实现；不要求重写判定器，也不把后台命令交给模型自行使用。

初始任务说明使用同一份，不能继续给 C 旧版 `operator-agent verify ...` 使用教程、仓库路径或源码阅读建议。C 通过正常安装接口发现真实工具和产品说明；这些说明是待测产品的一部分，不额外写一份只用于实验的捷径提示。

## 共同验证与首轮范围

原生 DSH 仍需具备正常的测试条件。两组获得相同公开测试材料，可经原生 bash/Python 执行一个通用测试入口；该入口只提交候选并返回共同验证服务的反馈，不包含 core 包、开发技能、代码生成或修复能力。它属于评测配套，报告应注明 A 是“原生 DSH + 公共测试材料”。C 另可通过真实插件 MCP 提交相同候选；所有路径都扣同一格的验证额度，不能各自另算次数。

插件反馈与公共测试反馈须来自相同契约、完整 L2、同一服务及等额开发机会。最终候选交给独立评估器，结果不再反馈给模型。不能用“只有 C 有 GPU 测试机会”的配置把基础测试条件差异当作插件收益。

首轮继续限定为外层模型写核、提交开发验证、按反馈自行修改，最多 2 次开发 L2 + 1 次独立最终 L2。`run/repair/bench` 和内层模型生成保持当前实验限制；结论限定于这一功能范围，不能声称覆盖发布插件的所有自动开发能力。若后续扩展功能范围，先另行冻结工具清单和共同预算。

模型沿用 `deepseek-v4.1-flash-1017`、medium、单次 32768 输出，每格最多 24 次模型调用、总输出预留 786432、墙钟 2400 秒。去掉 B 不给 C 增加单格额度。使用当前 GPU2 共享条件时仍须重新观察并冻结设备、常驻 PID、显存和负载条件，不复用旧资源观察作为新执行凭据。

预算优化不靠降低 medium 思考强度或缩小 32K 单次输出上限。共同提示给出不额外收费的软节奏：前 2 次调用确认任务与入口，争取在第 6–8 次前首次验证，最后 2 次优先交付现有最佳候选；不注入中途提醒，也不增加额度。逐格保留预留/完成/中止调用和 DSH usage；网关另记调用序号、受控故障阶段/代码、HTTP 状态、子进程清理事实与 outcome，不保存凭据、端点、请求或原始异常文本。网关诊断标注 provider billing unknown，因此能区分本地调用预算耗尽与传输/响应设施异常，但不能替代服务商账单。

## 必须落地的隔离变化

旧 C 的 `PYTHONPATH`、`operator-agent` shim 和公共 core 只读挂载不能沿用。仅删除 PATH 项或在提示里说“不要读源码”不够，还要拒绝按绝对路径读取、`python -m`、直接导入、链接和子进程绕行。

真实 MCP/core 服务应置于受试进程读取边界之外，或采用能达到同等边界的服务配置；DSH 仅持有正式工具连接。复用现有监督验证服务与真正的 MCP schema/instructions，避免为了方便另造一份假产品工具。插件加载所需工件不等于向模型挂载整个项目仓库。真实用户部署同样应只需安装配置和调用插件，无需阅读或修改核心实现。

## 无模型验收与后续批次

先实现并验收：

1. A/C 的 `operator-agent` 不在 PATH，core import 与绝对路径读取均失败，自己的候选文件及共同测试入口正常可用。
2. C 的实际 MCP 工具可发现、可提交候选、可接收失败反馈并修正；A 无对应插件/MCP 工具。使用同一服务核对反馈和额度，拒绝通过其他调用路径多拿验证机会。
3. 保留原有跨组候选、私有账本和凭据读取拒绝，源码/运行时身份校验、取消及异常输出留存。源码隔离探针不自动证明完整网络/IPC 隔离。
4. 两组 schedule、轮换顺序、独立工作区、预算、固定分母及 C−A 汇总支持新的 arm 集；旧 ABC 汇总与证据仍可读取，但不能授权新启动。
5. 验收网关脱敏错误阶段留痕；不得通过隐式重试掩盖旧批次 Softmax/B 的 502 unknown。

无模型探针证据：[A/C readiness 报告](../../output/plugin_completion/20261029-s5-plugin-only-readiness-v1/summary.json)。实际 DSH 在脚本化假模型下，两组各完成 10 个受控请求；首次候选写入观察在第 5 个 DSH 步骤、首次绑定验证反馈在第 6 步。每组都使用 2 次开发验证，额外公共提交被拒；C 发现真实 MCP schema/instructions 并通过 MCP 得到失败后成功的反馈，A 没有插件/MCP。两组都不能导入/执行 core、从绝对路径读取 core 或仓库、读私有账本/凭据/对照候选或通过子进程/硬链接绕过；共同公开测试入口可读。该结果是脚本化行为与权限边界验收，不是模型效率/质量证据。

当前代码入口：`benchmarks/s5_plugin_env.py`、`s5_plugin_rpc.py`、`s5_plugin_probe.py`、`s5_plugin_flow.py`、`s5_plugin_summary.py`、`s5_plugin_workflow.py`。本批计划固定 3 个任务、A/C、medium、每次 32K、每格 24 次调用和 2400 秒墙钟；执行器需要准确计划哈希与成功 readiness 报告，并在每格前检查 GPU 身份、至少 8 GiB 可用显存、利用率不高于 5% 和允许 PID。普通调用预算耗尽保留为非完成并继续后续格；网关/隔离/验证设施 unknown 会停止后续派发。本次正按该规则在第三格停止。

限制：已验证的是 macOS 文件读取边界和本机 MCP/HTTP 路径；探针明确记录 `network_isolation_verified=false`，没有证明网络仅能连接预算网关，也没有证明同 UID 恶意进程或宿主层进程逃逸不可行。本次结果因此保持探索性且 `formal_s5_credit=false`。若继续实测，须针对验证器传输 unknown 排查后新冻结计划、重新核对 GPU2 资源；不能重派本批 unknown 格或复用旧九格授权凭据。

后续样本仍可按 3 项历史任务 × A/C = 6 格设计；本批已冻结但未完整完成。若优先加速下一轮，可先选 1 项任务 × A/C = 2 格，但结果仅适用于该任务，不能推广为跨算子结论。更大规模的 6 项任务 × 每组 2 次仍是 24 格；任务清单内容哈希 `79fb8b03ee0514d67a354e24b78622fb668a7d27e3592ad3d1144ee2dc74bbd2` 保持来源记录。不得用旧九格预算与哈希直接启动。
