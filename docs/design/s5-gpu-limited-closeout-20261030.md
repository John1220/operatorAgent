## 3. 执行优先级

### P0：不占 GPU，先把已有成果变成可交付物

1. 冻结当前完整交付实现，包含监督驱动、`operator_agent/`、`remote_scripts/`、插件、prompts/skills 与构建元数据；生成 wheel、插件包和 SHA256 清单。与正在编辑的工作区分离，执行期只读；不能仅保存旧计划列出的部分文件。
2. 收集并备份历史原始证据、候选、契约、依赖与设备记录、模型预算、恢复验收和中断批次。原始私有档案与脱敏分享包分开，副本离线核对哈希及引用。远端环境如尚有本地未保存的版本/日志，趁访问仍可用时只读导出。
3. 写 S5 结项报告：按批次保留计划分母、已派发、通过、确定失败、设施 unknown、未执行；不合并异版本成绩。结论为“功能案例成立，整体贡献未建立”，不重新计算看起来更好的实验分母。
4. 在仓库外临时环境安装冻结工件，完成依赖检查、MCP 握手与发现、固定输入的无模型验证探针和身份稳定检查。此次结果只适用于实际构建版本；旧 S6 安装检查不自动继承到新版本。

交付：完整冻结版本、私有证据归档、脱敏案例包、可重算的结项报告。无需新增真实模型请求或 GPU 计算。

### P1：若还能留一个 GPU 窗口，只补“当前安装包可用”

这是新增信息最多的最小真机验收：从仓库外使用已安装工件，经实际插件注册的 MCP 验证入口提交一个已知正确的 LayerNorm 候选，固定 H20 身份，取得完整 L2 反馈并核对候选/契约/回执哈希。不让模型重新生成，不重复做已证明的 DSH 修复会话；标准客户端发起的 MCP 验收如实标记为安装工件验收。

- 复用一个明确来源的历史通过候选；候选与当前契约的适用性仍由本次完整 L2 判定。
- 先核对完整实现快照及远端 runner 身份，再检查设备/共享资源；不停止其他服务，不为抢时间弱化正确性套件。
- 新增真实模型调用 0；最多一次完整 L2，监督验证限时 600 秒。历史单次验证约 106–138 秒，**建议预留 10–20 分钟操作窗口，属于估算而非保证**；配置和打包先在 CPU 上完成。
- 通过即保留安装工件、实际调用参数、设备和环境、候选、完整 suite、反馈及原始日志；设施错误保留 unknown，不自动重复跑，不修代码后覆盖这次记录。
- 本项填补当前工件的真机可用性，不产生 A/C 优势结论，也不将历史修复改记为当前版本实测。

若 GPU 即将失效，P1 可以暂缓，已有历史实测仍可作为明确标注版本和日期的项目证据。GPU 时间不应被等待长模型答复占满。

### P2：有额外窗口才做性能补验

对推理性能岗位，一份合格、可解释的性能报告比再增加简单算子的 L2 成功格更有价值。优先补求职主线中已经明确的性能证据缺口；插件本身没有必须新增性能数字的要求。

若只补本仓的性能判定案例，可从已经量尺预检可裁决的 4096³ Matmul 开始，冻结候选、形状、基线和设备，先完整 L2，再做合格 L3 首测及独立确认；不做在线搜索、不新增模型、不预设候选一定快于基线。旧候选在旧版本的读数不能替代新版本验证。共享卡干扰、计时资格不合格或传输 unknown 则如实停下。此项耗时需执行前另估，不挤占 P1，更不为写加速比而无限调参。
