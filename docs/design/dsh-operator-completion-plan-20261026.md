## 1. 范围与起点

插件服务「生成／修改 → 验证 → 测速 → 根据结果修复」的算子开发闭环。推理性能归因与引擎改动由另一条项目主线承担；本计划不新增推理性能诊断插件。

2026-10-26 对比评审基于 HEAD `2f2d281` 的**当前工作区**，包含未提交与未跟踪改动。该提交号不能单独复现被评审的全部实现。以下是起点，不是待重建功能：

| 能力 | 已有事实 | 证据边界 |
|---|---|---|
| DSH / MCP / CLI 接入 | 七个工具、斜杠命令、打包配置与宿主契约测试 | 当前发行物仍需独立的干净安装验收 |
| 编译、正确性、性能与测量资格判定 | 既有 Verifier、measurement、eligibility 和失败路由 | 不能用单元测试数量替代真实开发收益 |
| 生成与修复 | 历史真机闭环、六例修复记录、十任务生成实验 | 历史生成实验与当前 `operator_run` 不是同一策略，不能移用成绩 |
| 预算与后台状态 | 有限默认预算、监督进程、状态查询、截止清理 | 截止清理不等于用户取消；本机停止也不证明远端或服务商停止 |
| 批量探索测量 | `operator_bench` 已有真机记录 | 人工提供候选的对比不等于插件自主搜索收益 |

本轮对比评审已运行两组 Python 针对性回归（229 + 168 = **397 通过**）及 DSH 插件/宿主回归（**53 通过**）。第二组首次受沙箱端口绑定和进程发现限制，允许本地假服务与进程检查后重跑通过。这不是全量回归，也未调用真实模型或 GPU；本文件创建时未重新运行这些测试。

主要参考：[插件说明](../../integrations/dsh-operator/README.md)、[开发方案评审](operator-development-review-20261026.md)、[生产任务预算](production-task-budget.md)、[历史插件实验](../dsh-plugin-evaluation.md)、[质量闭环](operator-quality-improvement.md)。

## 6. S3：资源预检误拒

### 已核缺口（实施前）

`resource_check._elem_bytes_from_code()` 看到 `tl.float32` 等字符串就按 4 字节估算；FP16 输入、FP32 累加的候选可能因此被过度估算并误拒。

定位：[资源预检](../../operator_agent/resource_check.py)。该修改涉及拒绝条件，实施前须核对设计规范和受影响的协议身份。

### 待办

- [x] 依据真实历史失败记录建立明确标注的重建回归，分清输入/中间缓冲区 dtype、累加器 dtype、tile 与 stages；原核缺失不补造原始证据。
- [x] 优先使用可确立的任务、缓冲区或原生编译资源证据；无法推导时返回未知/交由后续原生检查，不凭字符串作确定拒绝。
- [x] 不把所有存储统一替换为任务 dtype；保留混合精度与流水线占用的表达能力。
- [x] 更新拒绝理由、证据来源及相关身份；不修改参考实现、数值容差或真实硬件资源上限。

### 验收

- [x] FP16 存储 + FP32 累加模式不因累加器字符串被误拒（已用重建回归验证；不据此推定原生合法性）。
- [x] 确实超限的配置仍被正确处理；动态或未知配置不伪造精确估算。
- [x] 注释、docstring、autotune 多配置与混合 dtype 的正反例通过。
- [x] 本地估算与真机编译证据分开记录；正式成功率评测使用修正后的冻结版本。

**完成记录（2026-10-26）**：工具契约 8、插件 0.1.8 以明确共享存储证据为拒绝/剪枝依据；未知继续原生检查，独立保存来源、缓冲区与配置。原 10-19 源码缺失，已用明确标注的重建回归复现旧 384 KiB 误判，并保留真实硬件上限与 1.2 slack。全量 5453 通过、1 跳过，DSH 58 通过，Golden 4/4；首轮旧测试迁移记录和最终冻结材料详见 [S3 验收](../status/dsh-operator-s3-20261026.md)与 [资源证据边界](resource-precheck-evidence.md)。未启动 S4–S6 或恢复 Q1。

## 10. 回归与执行纪律

- 实现改动先增加能暴露原问题的正反例，再运行相关模块回归；共享协议/判据变更完成后运行仓库要求的完整回归与 Golden，不因本次编写文档重复运行全套。
- Python 使用项目中已有 pytest 的解释器，运行 `python -m pytest tests/...`，避免裸 `pytest` 误收集真机 driver。开发机器默认 `python3` 可能不是已有测试环境。
- DSH 测试入口为 `npm test`（工作目录 `integrations/dsh-operator/`）。本地假服务因沙箱初始化失败时，区分环境限制与产品缺陷。
- 真实实验遵循仓库既有计划冻结、资源、预算与授权规则；已有有效授权适用时不重复索要。授权不足或需要恢复已暂停范围时，先完成可审阅的具体计划。
- 不改生产服务，不用测试污染真实语料；既有无效/未知测量和独立确认规则保持。
- 每项完成后补写实际修改、运行条件、回归结果与证据位置；不只勾选「已完成」。
