# v0.8 任务族选型定案：性能基线认 eager 组合，不认厂商库

状态：**定案**（2026-11-13，用户批准方向1）。本文只定**选型规则**；具体任务清单与基线算子序列
在下一轮预登记时逐项冻结，不在这里提前承诺。

## 1. 决策

后续 A/C 对照与性能轮的入选任务，**性能基线必须是 eager PyTorch 组合（未融合的算子序列），
不选 cuBLAS / SDPA / cuDNN 等厂商库**。正确性参考实现不变（仍须已标定 profile）。
只有库基线、没有可信 eager 组合基线的任务（如纯 matmul），**只进交付数对照，不进性能主张**。

## 2. 依据（定量，均为已归档读数）

1. **对厂商库这条轴当前为负，且插件机制不改变它**：
   - matmul 4096³ fp32 候选 `0.37–0.38×` cuBLAS（IEEE 同精度基线）；
   - attention S=4096 `0.8608×` SDPA（`valid` L3，8 条 case 全过）。
   插件提供的是验证/反馈/预算闭环，**不抬高核的峰值性能上限**；对成熟库的赢面结构性低。
2. **对 eager 组合已有正读数，赢面条件可达**：LayerNorm 16384×6144 fp32 相对 PyTorch Eager
   `1.4135×`（`valid`）。**这是手写核经 CLI/core 的单形状历史实测，不是模型生成、不是插件增益**——
   它只证明「赢 eager 组合」这个条件本身可达，不证明插件能复现它。
3. **生态位与 AKG 对比一致**：编译器路线（多面体/MLIR）吃已知算子、正确性由构造保证；
   插件的不可替代处是**没有库可用的长尾/融合算子 + 真实 GPU 验证闭环**。选型往这个生态位靠。

## 3. 选型规则（可执行，逐条登记）

1. **正确性前提不变**：任务必须有可信参考实现与已标定容差 profile（L2 的前提）。
2. **性能基线 = eager 组合**：登记基线的**具体算子序列**（例如 `x.float() → mean → var → rsqrt → …`），
   不写「PyTorch」这种笼统串；基线类型字段认 `baseline_type`，不认显示串。
3. **优先长尾/融合族**（举例，非承诺）：fused layernorm+residual、rmsnorm、softmax+mask+scale 融合、
   attention 变体（已有 profile）、量化/反量化融合。门槛是「已有 profile，或可在零机时下完成标定」。
4. **逐任务登记噪声窗口探针通道**：按形状/算子/dtype 单独做，**不许继承** 4096³ 的读数；
   无合格探针窗口的任务，性能记 `unknown`，不进主张。

## 4. 对 P1 性能测量与预登记的影响

- 预登记的性能主张改为两层：**两臂同契约 parity（不劣于）** + **对 eager 组合的加速比**；
  不再以「追平 cuBLAS/SDPA」为目标。
- matmul/attention 对库的负读数**保留为历史事实**，不作为插件性能主张，也不删改。
- attention 的正确性参考仍可用 SDPA，但**性能基线**换成 eager attention 组合；两者分开登记。
- 终评仍止于独立 L2 的交付判定；性能 L3 是另行预登记的测量轮，不混进交付数结论。

## 5. 边界与不变量

- 选型只改变**赢面条件**，不改变测量纪律：valid/degraded/unknown 三态、窗口探针、
  IEEE/TF32 基线纪律、launch 地板占比，全部照旧。
- **不承诺**任意长尾算子都能赢 eager 组合；没有合格读数就是 `unknown`，不补数、不放宽。
- 对外表述禁列表仍然有效：不写「性能全面达标」「显著优于 DSH」，不把单形状历史读数归因于插件。
