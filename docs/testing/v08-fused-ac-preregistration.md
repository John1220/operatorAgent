# 融合任务 A/C 预登记草案：插件工作流能否在同等预算内交付达标的 fused 核

**2026-11-17 起草 · 状态：草案。** 头寸门（[融合头寸预登记](v08-fused-headroom-preregistration.md)）
已通过：手写 fused 核比 eager 两 kernel 快 55.14%。本轮问的是**工作流**：
同样的任务、同样的预算，裸 DSH（A）与 DSH+插件（C）各自能不能**自己交付**一个通过完整 L2 的融合核。

本文件不预设结论。冻结前需确认 §11 的四个参数；冻结后不许原位改预算或判据。

## 1. 研究问题

> 在同一个 `residual add + LayerNorm` 任务上，A/C 两臂从**空起点**出发、使用**相同模型/采样/预算/独立终评**，
> C 臂（插件 + 其文档化工作流）交付的达标核数量，是否比 A 臂（裸 DSH + 等价事实）更多？

主指标是**交付数**（独立终评通过完整 L2 算交付），不是性能。性能与调用数只作次级观测。

## 2. 与已有轮次的关系（别混轴）

| 轮 | 问什么 | 结论 |
|---|---|---|
| v6 A/C | 弱宿主上交付数 | `reproduced`（每轮 +1，插件臂 3–9 次调用，裸臂用满 20 次） |
| P1 | 一次交付核的性能 parity | `C_worse_observed` |
| P2 | optimize 诊断提示的增量 | `no_increment_observed` |
| D2 | 参数层/结构层余量 | `no_increment` / `structure_hurts` |
| 融合头寸 | 融合本身有没有提速空间 | `headroom_confirmed`（+55.14%，手写核） |
| **本轮** | **谁能交付达标的融合核、花多少调用** | **待测** |

头寸门只证明“任务值得做”；它**不**证明插件能交付这样的核，也不证明 A 交付不了。

## 3. 任务与判据

- **任务**：`fp16 32768x6144 residual add layernorm`，`Y = LayerNorm(X + R)`，末轴、总体方差、
  `eps=1e-5`、无 affine，X/R/Y 同形 fp16。
- **冻结契约**：`88f248ae4725b0e2…`；profile `builtin-fused-layernorm-residual-fp16-cuda-v1`；
  atol `5e-3`、rtol `1e-2`、rho `1.0`；参考 digest `c9aea6ac…`；套件 digest `652f65b1…`（32 case）。
- **交付（主指标）**：该格最终源码在 supervisor 的**独立终评**（`purpose=final`）里通过
  **完整 L2（32 case + 主用例）**。不要求 L3 达到某个加速比。
- **性能（次级）**：独立 L3 的 `speedup_vs_baseline`（`pytorch_eager` = fp16 add + native LN），
  需 `measurement_validity=valid` 才报；当窗 preflight 单独登记，不用它改交付判据。
- **规则**：不自造 eps/affine/轴；不支持 bf16/affine/非末轴。

## 4. 两臂

| 臂 | 工具面 | 拿到规格的途径 | 验证 |
|---|---|---|---|
| **A（裸 DSH）** | 普通 shell / 读写 / 编辑 + `check.py`（stdlib 客户端，提交走 supervisor） | 只有 context pack：任务声明、ABI（X/R/Y）、数值契约、容差、布局与规则、预算 | 同一个 supervisor 契约，最多 8 次验证 |
| **C（DSH + 插件）** | 普通工具关掉，只有插件 MCP 工具（`operator_context` / `operator_verify` / …） | `operator_context` 一次性发布：ABI、判据、布局、规则、候选 suite 清单 | `operator_verify` 同一冻结契约，最多 8 次（含 1 次终评预留） |

两臂**共用同一个 supervisor 判据**：同一份冻结契约、同一份 L2 套件、同一张 H20、
同一次独立终评。C 的待遇是“插件 + 其文档化工作流”（v6 已定：工作流本身属于 treatment，不拆成单个字段）。

## 5. 公平控制（继承 v6 + 本轮新增）

必须同时成立，缺一条该对作废：

1. **Repo-blind**：两臂工作区都看不到本仓、历史回执、计划文件与插件实现；C 臂的插件以已安装形态提供。
2. **ABI 等价**：A 的 context pack 与 C 的 `operator_context` 在**任务事实**上逐字等价
   （输入名/形状/dtype/strides、输出、eps/方差、容差、32 条 case 的布局与值模式、性能基线）。
   有差别的地方只能是 **C 多出的工具与工作流**，不能是 A 缺事实。
3. **采样身份六字段逐字一致**：`model / temperature / n / max_tokens / enable_thinking /
   reasoning_effort`；每条能从 `cell/outer-requests/*.json` 核对。
4. **预算一致**：模型调用、单次输出预留、总预留、墙钟、验证次数、GPU 卡与 UUID 完全相同。
5. **空起点**：两臂都不提供融合核、不提供 seed 源码；只有任务与事实。
6. **仪器失败 ≠ 候选失败**：钉卡失败、别人抢卡 OOM、墙钟超时、沙箱/网关抖动记 `unknown` 并按
   §10 重跑，不计入任一臂胜负。
7. **v6 的七个仪器缺陷全部按已修状态核对**：输出上限 32768/预留 40960、流式截止按实测吞吐、
   MCP 工具超时覆盖分钟级 L2、两臂采样一致、网关不拒 40960、A 臂工作区隔离、C 臂真拿到插件工具。

## 6. 模型与采样（待确认）

- **提议**：`Qwen3.8-27B`（本地 vLLM，GPU7 侧），`reasoning_effort=xhigh`，`enable_thinking=true`，
  `max_tokens=32768`，单次预留 `40960`，`n=1`，`temperature=0.1`。这是 v6 复现轮的弱宿主档位。
- **冻结前 smoke（不计入正式格）**：用当前 Coder 全量提示（11 配方）连跑 2 次，确认
  `finish=stop` 且核源码完整发出；若在 40960 撞 `length`，**先停下来**决定换 medium 还是收窄提示，
  并把决定写进冻结件——不许在正式格里换档。
- 任何换档都会改判据身份，需新计划编号；不许在跑完第一对后换。

## 8. 格与顺序

- pair-1：**A → C**；pair-2：**C → A**（反序抵消顺序/热机效应）。
- 每格独立工作区、独立 supervisor run、独立终评证据；两对证据互不复用。
- 两对都用同一份冻结计划与同一模型端点哈希；端点漂移则停。

## 9. 判读

- **单对**：`交付数差 = C交付 − A交付`（本任务单值 0 / ±1）。C 交付且 A 未交付 ⇒ `+1`。
- **整轮**：两对都必须可判且同向 `+1` ⇒ **`reproduced`**，`formal_gain_claim=true`；
  两对都是 0 ⇒ **`delivery_parity`**（交付数无差，按 §9 次级指标描述调用数）；
  出现 `−1` ⇒ **`contrary`**；任一对 `unknown` 且无法重跑到可判 ⇒ **`unknown`**。
- **次级指标**（不授正式信用）：到交付的模型调用数、验证次数、墙钟、L3 speedup（`valid` 才报）。
  v6 已证明墙钟方向不一致，故墙钟只描述、不判胜负。
- **禁止**：把“调用数更少”写成“开发更快/人时更少”；把人时、成本外推；把本轮的交付数结论
  外推到融合族之外或强模型。

## 10. 停止规则

- 预算耗尽即停，不追加；不中途改判据、不放宽容差、不删 case。
- 契约/源码哈希不符 ⇒ 拒配；模型端点哈希变化 ⇒ 停。
- 连续两格 `unknown`（仪器/设施）⇒ 本轮 `unknown`，不追加第三对。
- smoke 未过（§6）⇒ 不冻结、不开正式格。

## 11. 待确认（冻结前必须定）

1. **模型档位**：27B/xhigh（v6 复现档，推荐）还是 27B/medium（避开 40960 撞顶风险）？
2. **对数**：2 对（推荐，能说“每对 +1”）还是先 1 对试跑（不授正式信用）？
3. **墙钟**：3600 s/格是否够（融合 L2 比 v6 任务慢）？
4. **A 臂是否给 32 条 case 清单**：推荐**给**（v6 的 `tested_layouts` 缺失曾被当成“插件独有事实”，
   本轮把 ABI 等价作为硬约束；若坚持不给，需在 treatment 定义里写明并接受更难的主张）。

## 13. 边界

- 结论限：这一条融合任务、32768×6144 fp16、弱宿主 27B、登记的 H20/GPU7、2 对正式格。
- 交付数结论**不**包含性能主张；性能只作次级观测，且以独立 L3 `valid` 为前置。
- 头寸轮的 55.14% 是手写核读数，不能当作任一臂的交付性能。
