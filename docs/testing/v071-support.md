# v0.7.1 支持清单（有限支持）

| 项目 | 说明 |
|---|---|
| 版本对象 | 产品 / Python **0.7.1**，DSH 插件 **0.2.1**，工具契约 **10** |
| 支持日期 | 2026-11-05 |
| 已验证宿主 | DSH **0.2.1-rc.2**、Node **24.14.1**；其他宿主组合需另行验收 |
| 交付形式 | 本地安装包、源码快照、验收记录与导出产物；公开包仓库发布另行执行 |

本版完善 v0.7 的 DSH 模型委托链路，保留独立 CLI 和原有模型直连路径。算子后端维护生成规约、角色模板、冻结任务及搜索状态，DSH 保留用户和项目上下文。普通 Triton Coder 可以看到任务声明的形状；FakeBackend 的 NumPy/math 执行限制注入生成和修复提示。

[v0.7.0 冻结支持清单](v07-support.md)保留为历史版本记录。本版保持该清单的有限任务范围，新增支持的是显式启用的固定 DSH 模型路由，不扩大算子、精度、布局或硬件承诺。开发工件的真实模型证据见[模型委托验收](../status/v071-model-relay-acceptance-20261105.md)；最终工件结果见[交付记录](v07-delivery.md) §12，两个工件身份分别保留。

## 1. 用户工作流与模型路由

| 路径 | 本版支持范围 | 证据与边界 |
|---|---|---|
| DSH 固定模型委托 | 在隔离 profile 中显式配置一组 provider/model，为 `operator_run`、`operator_repair` 发送内层文本模型请求 | 真实模型生成、修复及 H20 流程已验收；转发默认关闭 |
| 模型上下文 | Python 构造角色消息，DSH 适配器发送请求 | 任务预算、temperature、maxTokens 和用量逐调用核对；用户/项目上下文不会自动混入算子角色消息 |
| 已验证服务商 | 阿里云 OpenAI Completions 路由，模型 `deepseek-v4.1-flash-1017` | 模型条目需配置 `compat.thinkingFormat: qwen`、`compat.maxTokensField: max_tokens`，实际出站字段为 `enable_thinking: false` 和 `max_tokens` |
| 独立入口 | CLI / MCP 原模型客户端继续可用；删除 `modelRelay` 并恢复 MCP 模型环境配置可回退到直连 | 配置与回退步骤见[插件说明](../../integrations/dsh-operator/README.md) |
| 在飞取消 | 本地任务进入 `cancelled`，worker 回收，DSH 模型流收到 abort | 服务商是否已停止执行和计费保持 `unknown`，已派发调用不退还任务预算 |
| 账本 | Python 保留任务预算及调用记录，服务商用量仅认已校验计数 | 缺失字段保持 `unknown`；API usage 对账不代表已建立费用或完整会话成本 |

DSH 持有服务商凭据，Python worker 使用该 profile 独立的本地转发凭据。服务监听 IPv4 回环地址，凭据文件为当前用户拥有的 `0600` 普通文件；目录、凭据和端口按 profile 分开配置。模型路由需与服务商实际协议匹配，不能仅凭宿主列出 `off` 就推断服务商收到了关闭思考字段。

当前 desktop 免费默认路由曾返回 `402 free_request_quota_exhausted`，尚无完整成功验收，不列为本版已验证服务商。该失败回执与其他已派发任务均保留；本版没有自动更换付费模型或启用隐式 fallback。

## 2. 算子、执行后端与运行时

| 项目 | 本版有限支持范围 | 验收依据 |
|---|---|---|
| 真机工作流 | H20 上 Triton FP16 Softmax `4096×4096` 连续布局主用例，显式 SSH | 新生成候选及独立终评通过契约内全部 **12 个 L2 用例**，源码和报告已导出 |
| 派生用例 | 仅上述冻结契约声明的连续及 strided 正确性用例 | 不外推未声明输入、任意主布局或其他形状 |
| FakeBackend | CPU Python + NumPy/math；可配脚本模型或真实模型 | 成功、修复和取消流程；执行及计时恒标 `FAKE / test_only`，`gpu_acceptance=false` |
| 控制面安装 | CPython 3.12，NumPy 为硬依赖 | 干净环境安装与入口回归以最终工件记录为准 |
| GPU 运行时 | H20、驱动 `580.105.08`、Python `3.10.12`、Torch `2.14.1+cu130`、Triton `3.8.0`、CUDA `13.0` | 验收前后核对同一 GPU 与运行时，以及 15 个 runner 文件哈希 |
| `local` / `mock` | 仅开发自检 | 不增加交付路径或真机支持资格 |
| 其他算子、精度、硬件或运行时 | 按实例另行验收 | Matmul、ReLU 的历史正确性证据仍归原记录；不视作本版安装工件新增工作流验收 |

内建完整 L2、冻结契约、输入保真、确定性及候选哈希等判据继续适用。版本升级不放宽容差或性能目标，不把能力发现结果当作支持资格。

## 3. 性能与收益

本轮开发工件的 H20 独立终评为 `L1=true / L2=true / L3=false`，speedup 读数 `0.803`，有效性为 `degraded`；launch 地板占实测时间 `14.7%`。该读数未建立性能提升、进展或长期记忆资格，不能用于公平 A/B 或业务收益主张。最终工件的读数及其资格单列在交付记录中。

本版交付范围是模型委托链路与已有正确性工作流。性能诊断和搜索增强继续归 v0.8，L3 未达标不被改写为达标，也不自动扩大本版开发范围。

## 4. 后续范围与重新验收条件

按会话自动选择模型、把内层调用归因到主会话、扩大服务商兼容范围仍待开发和验收，未列为本版封版前置。第二宿主、框架端到端接入、非 CUDA 迁移、任意失控核恢复及敌意代码隔离沿用 v0.7.0 的边界。

以下变化需要重新核对相关证据，不沿用已有资格：随包执行源码或 runner、生成提示或 skills、冻结契约或 L2 用例/容差、目标卡身份、驱动或 Torch/Triton/CUDA 运行时，以及 DSH 适配器或服务商协议发生变化。主会话切换模型不会自动修改固定转发路由；更换路由时应重新核对请求字段、用量和取消回执。
